## 2. GDS Core Engine Architecture  

| Component | Description | Typical Latency* |
|-----------|-------------|------------------|
| **GDS Front‑End (Amadeus / Sabre)** | Unified SOAP/REST gateway exposing **Air Shopping**, **Seat Map**, **Fare Quote** services. | 120‑250 ms |
| **Airline Schedule Feed** | Direct carrier schedule file (SSIM‑based) refreshed **every 15 min**; includes operating carrier, flight number, departure/arrival airports, aircraft type, and **effective dates**. | 30‑70 ms |
| **Cabin Class Inventory Engine** | Real‑time PNR‑based inventory lock, seat‑map push, **Class of Service (Y, M, B, H, Q, etc.)** availability. Updated on each booking, cancellation, or inventory release. | < 50 ms |
| **CRS Hotel Rate Engine** | Direct connection to hotel Property Management Systems (PMS) via **OpenTravel Alliance (OTA) XML** or **JSON‑API**. Rate plans (BAR, corporate, negotiated) are pulled **every 5 min**. | 80‑180 ms |
| **Cache Layer** | In‑memory Redis cluster for 2‑minute hot‑data caching (flight‑leg, cabin‑class, hotel‑rate). Guarantees sub‑10 ms reads for repeat queries. | < 10 ms |
| **Security Gateway** | Mutual TLS, OAuth 2.0 client‑credentials flow, and token‑based request signing (HMAC‑SHA256). | — |

\*Measured under typical production load (≈ 10 k QPS).

## 3. Direct Airline Schedules  

### 3.1 Data Model (JSON Example)  

```json
{
  "flight_id": "TK1234",
  "carrier": "TK",
  "origin": "IST",
  "destination": "LHR",
  "departure": "2026-10-15T08:30:00+03:00",
  "arrival":   "2026-10-15T11:45:00+00:00",
  "aircraft": "A321",
  "operating_days": ["MON","WED","FRI","SUN"],
  "effective_from": "2026-09-01",
  "effective_to": "2027-03-31",
  "cabin_classes": [
    {"code":"Y","seats_total":30,"seats_available":12},
    {"code":"M","seats_total":20,"seats_available":5},
    {"code":"J","seats_total":8,"seats_available":0}
  ]
}
```

- **`cabin_classes`** reflects **live inventory** pulled from the airline’s PNR system.  
- **`operating_days`** are derived from the carrier’s **SSIM schedule** and are refreshed every 15 min.  

### 3.2 Schedule Retrieval API  

```
GET /v1/gds/airlines/schedules?origin=IST&date=2026-10-15&max_results=200
Headers:
  Authorization: Bearer <access_token>
  X-Request-ID: <uuid>
```

- **Response**: Array of schedule objects (as above).  
- **Error Codes**: `429` (rate‑limit), `503` (GDS down), `400` (invalid parameters).  

### 3.3 Integration Point  

Insert the **flight search widget** where users can filter by origin/destination, date, and cabin class:  

```
[ GDS_FLIGHT_SEARCH_WIDGET ]
```

The widget internally calls the endpoint above, renders a **real‑time seat‑map**, and returns a **booking token** that can be passed to the downstream PNR creation service.

## 4. Live Cabin‑Class Availability  

### 4.1 Fare‑Family Construction  

| Cabin Code | Fare Family | Typical Restrictions |
|------------|-------------|----------------------|
| Y          | Economy     | Refundable / Changeable (optional) |
| M          | Economy     | Non‑refundable, 1‑way change fee |
| B          | Premium Eco | Extra legroom, free baggage |
| J          | Business    | Full flexibility, lounge access |
| C          | Business    | Discounted, limited changes |
| F          | First       | All‑inclusive, priority boarding |

- **Availability** is **atomic** – a seat lock request (`POST /v1/gds/airlines/lock`) reserves the exact cabin class for **90 seconds** pending payment.  

### 4.2 Real‑Time Availability API  

```
POST /v1/gds/airlines/availability
{
  "flight_id": "TK1234",
  "cabin_codes": ["Y","M","B","J"]
}
```

**Response**  

```json
{
  "flight_id": "TK1234",
  "availability": [
    {"code":"Y","available":12,"price":"EUR 210.00"},
    {"code":"M","available":5,"price":"EUR 180.00"},
    {"code":"B","available":2,"price":"EUR 260.00"},
    {"code":"J","available":0,"price":"EUR 620.00"}
  ],
  "currency":"EUR",
  "timestamp":"2026-09-19T12:34:56Z"
}
```

- **Price** reflects the **current fare rule** (including taxes, surcharges, and airline‑specific markup).

## 5. CRS Hotel Rates (Official Property Rates)  

### 5.1 Rate Plan Taxonomy  

| Rate Code | Description | Applicability |
|-----------|-------------|---------------|
| BAR       | Best Available Rate | Public, no restrictions |
| CORP      | Corporate Contract | Pre‑negotiated corporate discount |
| GDS       | GDS‑only Rate | Only visible via GDS/CRS channels |
| PREPAY    | Pre‑pay, non‑refundable | Lower price, strict cancellation |
| FLEX      | Fully refundable | Higher price, flexible dates |

### 5.2 Sample Hotel Rate Payload  

```json
{
  "hotel_id": "IST001",
  "property_name": "Istanbul Grand Plaza",
  "room_type": "Deluxe King",
  "rate_plan": "CORP",
  "currency": "EUR",
  "price_per_night": 145.00,
  "available_rooms": 7,
  "check_in": "2026-10-20",
  "check_out": "2026-10-23",
  "amenities": ["Free Wi‑Fi","Breakfast Included","Airport Shuttle"]
}
```

- **`available_rooms`** is sourced from the hotel’s **PMS inventory** via the CRS in **real‑time** (push/pull every 5 min).  

### 5.3 Hotel Rate Retrieval API  

```
GET /v1/crs/hotels/availability?city=IST&check_in=2026-10-20&check_out=2026-10-23&guests=2
Headers:
  Authorization: Bearer <access_token>
```

- **Response**: List of hotel objects (as above) sorted by **price** or **rating** per client request.  

### 5.4 Integration Point  

Place the **hotel inventory widget** on the property‑detail page or after flight‑search results:  

```
[ CRS_HOTEL_INVENTORY_WIDGET ]
```

The widget consumes the endpoint above, displays live room count, and returns a **reservation token** that can be combined with the flight booking token for a **single‑transaction** multi‑modal itinerary.

## 6. White‑Label Direct Booking Integration Blueprint  

### 6.1 High‑Level Flow  

1. **User initiates flight search** → `[GDS_FLIGHT_SEARCH_WIDGET]` → Calls **Schedule API** → Shows live cabin‑class matrix.  
2. **User selects cabin** → **Lock request** (90 s) → Returns **flight‑booking‑token**.  
3. **User proceeds to hotel search** → `[CRS_HOTEL_INVENTORY_WIDGET]` → Calls **Hotel Rate API** → Shows live room inventory.  
4. **User selects hotel** → **Room lock** (120 s) → Returns **hotel‑booking‑token**.  
5. **Combined itinerary** → **Create PNR** (`POST /v1/gds/pnr/create`) with both tokens → **Payment capture** → **Ticketing & Confirmation**.  

### 6.2 API Contract Summary  

| API | Method | Endpoint | Auth | Rate‑Limit |
|-----|--------|----------|------|------------|
| Flight Schedule | GET | `/v1/gds/airlines/schedules` | OAuth2 client‑cred | 5 000 req/min |
| Cabin Availability | POST | `/v1/gds/airlines/availability` | OAuth2 client‑cred | 3 000 req/min |
| Seat Lock | POST | `/v1/gds/airlines/lock` | OAuth2 client‑cred | 2 000 req/min |
| Hotel Availability | GET | `/v1/crs/hotels/availability` | OAuth2 client‑cred | 4 000 req/min |
| Room Lock | POST | `/v1/crs/hotels/lock` | OAuth2 client‑cred | 2 500 req/min |
| PNR Creation | POST | `/v1/gds/pnr/create` | OAuth2 client‑cred | 1 500 req/min |

All endpoints require **mutual TLS** and **HMAC‑SHA256** request signing.  

### 6.3 Security & Compliance  

- **PCI‑DSS**: Payment data never traverses the GDS/CRS; only tokenized payment IDs are stored.  
- **GDPR**: Personal data is encrypted at rest (AES‑256) and retained for a maximum of 30 days unless a booking is confirmed.  
- **IATA/ATA**: Fare construction follows **IATA Fare Rules** (Rule 1‑9) and **ATA 100** for ancillary services.

2. **Rate‑limit (429)** → Queue request, respect `Retry-After` header.  
3. **Data mismatch** → Fallback to **cached snapshot** (max age 2 min) with UI banner “Inventory may be stale – please reconfirm”.
