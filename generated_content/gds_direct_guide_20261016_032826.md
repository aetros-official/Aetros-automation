## 4. Integration Architecture & Compliance

### 4.1. Zero-Dependency Guarantee
- **No Affiliate Links:** All URLs, API endpoints, and payment redirects point exclusively to carrier CRS or hotel CRS via the GDS secure gateway.
- **Fare Integrity:** Prices displayed are the exact amounts charged to the corporate payment terminal. No hidden fees, service charges, or affiliate commissions are added.
- **Ticketing & Reservation:** All PNRs (Passenger Name Records) and hotel reservations are created directly in the carrier’s and hotel’s systems, ensuring full compliance with IATA and IATA-617 standards.

### 4.2. API Technical Specifications
- **Protocol:** RESTful API / SOAP (for legacy GDS interfaces)  
- **Authentication:** OAuth 2.0 Client Credentials Flow with GDS-specific keys.  
- **Error Handling:**  
  - `ERR_STOCK`: Real-time inventory sync failure. Retry logic implemented with exponential backoff.  
  - `ERR_RATE_CHANGE`: Price has changed since last poll. Widget must refresh with new BAR before allowing booking.  
  - `ERR_PNR_FAIL`: Direct PNR creation failed. Fall back to manual intervention alert.

### 4.3. White-Label Implementation Guidelines
1. **Embed Widgets:** Insert `[GDS_FLIGHT_SEARCH_WIDGET]` and `[CRS_HOTEL_INVENTORY_WIDGET]` directly into the customer-facing frontend.
2. **Data Binding:** Bind widget outputs to your central order management system (OMS) using the provided JSON schema.
3. **Payment Gateway:** Connect directly to the GDS-authorized payment processor to ensure card-not-present (CNP) transactions are settled directly with carriers and hotels.
4. **Monitoring:** Implement real-time logging of all GDS/CRS API calls to track latency, error rates, and transaction volumes.
