## Authoritative Travel & Fare Analysis Guide  
*Live Direct GDS (Amadeus / Sabre) & CRS (Hotel) Data – Istanbul (IST) Hub*

## 📌 Scope & Intent  

This guide is a **technical blueprint** for embedding **direct‑booking** capabilities into any white‑label travel portal. All fare, schedule, cabin‑class, and hotel‑rate data are sourced **exclusively** from:

| Source | Type | Coverage | Frequency |
|--------|------|----------|-----------|
| **Amadeus Core Engine** | GDS – Airline Schedule & Availability | Global, with focus on **IST** (Istanbul) origin/arrival | Real‑time (≤ 2 sec latency) |
| **Sabre Core Engine** | GDS – Airline Schedule & Availability | Global, with focus on **IST** | Real‑time (≤ 2 sec latency) |
| **CRS Hotel Central System** | Hotel Property Rates & Inventory | All CRS‑connected hotels in Istanbul (IST) | Real‑time (≤ 2 sec latency) |

> **Zero reliance on affiliate or meta‑search networks** – every data point is a **direct pull** from the carrier/ hotel CRS.

## 1️⃣ Architectural Overview  

```
+----------------------+      +----------------------+      +----------------------+
|  Front‑End UI (SPA)  | <--->|  API Gateway (REST) | <--->|  Core AI Engine       |
+----------------------+      +----------------------+      +----------------------+
                                   |   ^   |
                                   |   |   |
                               +---+---+---+---+
                               |   Data Connectors   |
                               |   (GDS / CRS)       |
                               +----------------------+
```

| Component | Responsibilities |
|-----------|------------------|
| **Front‑End UI** | Renders `[GDS_FLIGHT_SEARCH_WIDGET]` and `[CRS_HOTEL_INVENTORY_WIDGET]`. Handles user interaction, token storage, and session‑level caching (TTL = 30 s). |

| **Core AI Engine** | Business‑logic layer: merges GDS/CRS responses, applies fare‑rules, taxes, surcharges, and performs **price‑elastic conversion** recommendations. |
| **Data Connectors** | Low‑latency adapters to Amadeus, Sabre, and Hotel CRS (SFTP/HTTPS/Message‑Queue). All connections use **mutual TLS** and **PCI‑DSS**‑compliant encryption. |

## 2️⃣ Direct Airline Schedule & Cabin‑Class Data  

### 2.1 Real‑Time Flight Search API (GDS)

**Endpoint**: `POST https://api.yourdomain.com/v1/flights/search`  

**Request Schema** (JSON)

```json
{
  "origin": "IST",
  "destination": "ANY",                     // use IATA codes; “ANY” for multi‑city view
  "departureDate": "2026-12-15",
  "returnDate": null,
  "cabinPreference": ["ECONOMY", "PREMIUM_ECONOMY", "BUSINESS", "FIRST"],
  "maxConnections": 2,
  "includeLiveCabinAvailability": true,
  "currency": "USD",
  "passengerCount": {
    "adult": 2,
    "child": 0,
    "infant": 0
  }
}
```

**Core Engine Processing Steps**

1. **Parallel Dispatch** to Amadeus & Sabre adapters with identical payload.  
2. **De‑duplication** of identical flight legs (same carrier, flight number, schedule).  
3. **Live Cabin Class Availability Merge** – each leg returns a **CabinClassAvailability** object:  

   ```json
   {
     "cabin": "BUSINESS",
     "availableSeats": 3,
     "fareBasis": "YQ1B",
     "price": {
       "amount": 842.50,
       "currency": "USD"
     },
     "taxes": [
       {"code":"US","amount":45.00},
       {"code":"AY","amount":12.30}
     ]
   }
   ```

4. **Fare Construction** – apply **carrier‑specific fare rules**, **tax tables**, and **dynamic pricing engine** (AI‑driven price elasticity).  
5. **Response Normalization** – single unified list sorted by **total fare (incl. taxes)**.  

**Response Example**

## 3️⃣ Official Hotel CRS Rates – Live Inventory  

### 3.1 Real‑Time Hotel Search API (CRS)

**Endpoint**: `POST https://api.yourdomain.com/v1/hotels/search`  

**Request Schema**

```json
{
  "cityCode": "IST",
  "checkIn": "2026-12-20",
  "checkOut": "2026-12-25",
  "rooms": [
    {"adults":2,"children":0}
  ],
  "includeRatePlans": true,
  "currency": "EUR",
  "rateFilter": {
    "maxRate": 250,
    "minRate": 50
  }
}
```

**Processing Flow**

1. **Direct CRS Query** – a SOAP/REST bridge to the central hotel reservation system.  
2. **Rate Plan Extraction** – each property returns **RatePlan** objects with **rateCode**, **price**, **cancellation policy**, **room type**, and **inventory count**.  
3. **Live Inventory Validation** – the engine checks **`availableRooms`** > 0 before exposing.  
4. **Currency Normalization** – if the CRS returns **multiple currencies**, the engine uses **real‑time FX feed** (FXCM) to convert to the request currency.  
5. **Rate‑Rule Application** – corporate contracts, promotional codes, and **dynamic markup** (AI‑driven) are applied *after* CRS price retrieval.

## 4️⃣ Integration Checklist – 100 % Direct‑Booking (No Affiliate Dependency)

| ✅ Item | Description | Validation |
|--------|-------------|------------|
| **API Keys** | Generate dedicated **GDS/CRS API keys** per environment (DEV/PROD). | Keys stored in **Vault**; rotate every 90 days. |
| **OAuth2 Provider** | Use internal **Identity Server** – no social login or affiliate SSO. | Access token must contain `scope: gds.read hotels.read`. |
| **Mutual TLS** | All outbound GDS/CRS connections require client certs. | Verify handshake logs show `TLS 1.3, cipher TLS_AES_256_GCM_SHA384`. |
| **Rate Limiting** | Enforce **strict per‑carrier quotas** (e.g., Amadeus ≤ 80 req/s). | Dashboard alerts on > 5 % breach. |
| **Caching Policy** | In‑memory cache (Redis) with **TTL = 30 s** for identical search payloads. | Cache‑hit ratio > 95 % in production. |
| **No Affiliate Scripts** | Audit the final HTML – **search for any `affiliate` or `track`** domains. | Automated CI job fails on detection. |
| **Compliance** | PCI‑DSS, GDPR (data residency in EU), and **IATA BSP** (if ticketing). | Quarterly external audit certificates attached. |
| **Testing** | End‑to‑end test suite: `flight-search → booking → ticket issuance` & `hotel-search → reservation → confirmation`. | 100 % pass on CI pipeline. |

## 5️⃣ Pricing & Conversion Optimisation (AI‑Driven)

1. **Dynamic Markup Engine** – calculates a **margin** based on:  
   - Historical conversion rate per carrier/ hotel.  
   - Real‑time demand signals (search volume, seat inventory).  
   - Customer segment (B2B vs B2C).  

2. **Price Elasticity Model** – a **gradient‑boosted regression** that predicts the optimal price point where **conversion probability** is maximized while maintaining target margin.  

3. **A/B Test Harness** – built‑in feature flag (`pricingModel=v1|v2`) to compare **static markup** vs **AI‑optimized** markup.  

4. **Revenue Dashboard** – real‑time KPI tiles: `Gross Booking Value`, `Net Margin`, `Average Fare per Cabin`, `Hotel ADR (Average Daily Rate)`.
