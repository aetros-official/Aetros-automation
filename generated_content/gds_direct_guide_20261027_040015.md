## 1. Executive Summary  
Your portal is now capable of delivering **direct, real‑time flight and hotel inventory** to your clients without relying on affiliate networks. By embedding the *GDS_FLIGHT_SEARCH_WIDGET* and *CRS_HOTEL_INVENTORY_WIDGET*, you gain:

| Feature | Benefit | Direct‑Source Impact |
|---------|---------|---------------------|
| **Live Cabin Class Availabilities** | Clients see exact seat types (Economy, Business, First) and rates | Real‑time Amadeus/Sabre feed |
| **Dynamic Hotel CRS Rates** | Rates reflect the most current hotel inventory and promotions | CRS API |
| **Zero Affiliate Margin** | You control the entire revenue stream | No third‑party commissions |
| **White‑Label UI** | Seamless brand integration | Customizable widget skins |

```
┌───────────────────────┐          ┌───────────────────────┐
│  Frontend Web Portal  │ <---->   │  Widget Container API │
│ (White‑Label Widgets) │          │  (Auth, Session Mgmt) │
└───────────────────────┘          └───────────────────────┘
             │                                 │
             ▼                                 ▼
      ┌───────────────────┐          ┌───────────────────────┐
      │  GDS Integration  │          │  CRS Integration       │
      │ Amadeus / Sabre    │          │  Hotel CRS (e.g.,     │
      │  Core Engine       │          │  e.g., Oracle Hospitality)│
      └───────────────────┘          └───────────────────────┘
             │                                 │
             ▼                                 ▼
      ┌───────────────────┐          ┌───────────────────────┐
      │  Real‑time API    │          │  Real‑time API         │
      │  Calls (OTA, XML) │          │  Calls (JSON/XML)      │
      └───────────────────┘          └───────────────────────┘
```

* **Stateless API Layer** – all widgets operate via HTTPS REST/GraphQL, no server‑side caching of inventory (to preserve 0% dependency on affiliates).  
* **OAuth 2.0 / Client Credentials** – secure token acquisition per vendor.  
* **Rate‑Limiting** – each vendor imposes a limit; use exponential back‑off to stay within quotas.

## 3. Data Model & Key Endpoints  

| Vendor | Endpoint | Request | Response |
|--------|----------|---------|----------|
| **Amadeus** | `GET /v1/flight-offers` | `{originLocationCode, destinationLocationCode, departureDate, adults, cabinClass}` | JSON list of flight offers with `availability` and `price` |
| **Sabre** | `GET /flight-search` | XML body (`<OriginLocation>`, `<DestinationLocation>`, `<DepartureDate>`, `<CabinClass>`) | XML response with `<SeatAvailability>` |
| **Hotel CRS** | `GET /hotel-offers` | `{cityCode, checkInDate, checkOutDate, rooms, guests, amenities}` | JSON with `roomType`, `ratePlan`, `availability` |

### Sample Amadeus Flight Search Request

```http
POST https://test.api.amadeus.com/v1/shopping/flight-offers
Authorization: Bearer {access_token}
Content-Type: application/json

{
  "source": "GDS",
  "searchCriteria": {
    "originLocationCode": "IST",
    "destinationLocationCode": "NYC",
    "departureDate": "2026-12-15",
    "adults": 2,
    "cabinClass": "ECONOMY"
  }
}
```

### Sample Hotel CRS Request

## 4. White‑Label Widget Integration  

The widgets are delivered as self‑contained iframes or JavaScript modules. They accept a single configuration object and return events (`onSelect`, `onCancel`, `onError`) for integration with your booking engine.

### 4.1 GDS Flight Search Widget

```html
<div id="flight-widget"></div>

<script>
  const flightConfig = {
    containerId: "flight-widget",
    gdsSource: "Amadeus", // or "Sabre"
    defaultParams: {
      origin: "IST",
      destination: "NYC",
      departDate: "2026-12-15",
      cabinClass: "ECONOMY"
    },
    callbacks: {
      onSelect: (offer) => {
        // offer contains flightSegments[], price, availability
        console.log("User selected:", offer);
      },
      onCancel: () => console.log("Search cancelled"),
      onError: (err) => alert("Error: " + err.message)
    }
  };
  GDS_FLIGHT_SEARCH_WIDGET.init(flightConfig);
</script>
```

> **Key Technical Notes**
> * The widget fetches data from your server’s proxy endpoint that in turn calls the Amadeus/Sabre API.  
> * All UI strings are overridable via the `i18n` property.  
> * The widget renders the **exact cabin class availability** – no artificial inventory.

### 4.2 CRS Hotel Inventory Widget

```html
<div id="hotel-widget"></div>

<script>
  const hotelConfig = {
    containerId: "hotel-widget",
    hotelSource: "OracleHospitality", // replace with your CRS vendor
    defaultParams: {
      cityCode: "IST",
      checkIn: "2026-12-15",
      checkOut: "2026-12-20",
      rooms: 1,
      guests: 2
    },
    callbacks: {
      onSelect: (room) => {
        // room contains ratePlan, roomType, price, availability
        console.log("Room selected:", room);
      },
      onCancel: () => console.log("Search cancelled"),
      onError: (err) => console.error(err)
    }
  };
  CRS_HOTEL_INVENTORY_WIDGET.init(hotelConfig);
</script>
```

> **Important** – The widget surfaces the **official CRS rates**. No conversion or markup is applied.

## 5. Real‑Time Availability & Pricing  

1. **Live Cabin Class Availability**  
   *Amadeus* returns `availableSeats` per segment; *Sabre* returns `<SeatAvailability>`.  
   The widget presents this data as a dropdown (e.g., “Economy – 3 seats left”).  

2. **Official Hotel CRS Rates**  
   Rate plans are returned with `effectiveDate` and `price`.  
   The widget calculates total cost by multiplying `ratePerNight * numberOfNights`.
