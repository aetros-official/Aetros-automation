## 1. Overview
The **Core AI Engine** connects directly to **Amadeus** and **Sabre** GDS cores and to the **central reservation system (CRS)** of partner hotels. All data flows are **zero‑dependency** – no affiliate or OTA middleware is used.  

Key benefits for a white‑label travel portal:

| Feature | Business Value |
|---------|----------------|
| **Live airline schedules** | Instant, authoritative flight times, frequencies, and operating carrier codes. |
| **Real‑time cabin class inventory** | Seats in Economy, Premium Economy, Business, First are fetched on‑demand, guaranteeing up‑to‑the‑minute availability. |
| **Official hotel CRS rates** | Directly negotiated contracts are surfaced without markup or third‑party commissions. |
| **Full API ownership** | End‑to‑end control of data transformation, caching, and UI rendering. |

## 2. Direct Airline Schedule Retrieval
### 2.1 Core GDS Endpoint  
```http
GET /gds/v1/flight/schedules
Host: api.coretravel.io
Authorization: Bearer <access_token>
Accept: application/json
```

| Query Parameter | Type | Required | Description |
|-----------------|------|----------|-------------|
| `origin`        | IATA | Yes      | Departure airport (e.g., `IST`). |
| `destination`   | IATA | Yes      | Arrival airport (e.g., `JFK`). |
| `departureDate` | ISO‑8601 (YYYY‑MM‑DD) | Yes | Desired departure day. |
| `maxResults`    | int  | No  | Upper bound of returned flights (default 200). |
| `carrier`       | IATA | No  | Filter to a specific airline (e.g., `TK`). |

#### Sample Response (truncated)
```json
{
  "requestId": "c7f2e5b9-4a1d-4c8a-9e2d-3d1b8e7f6a21",
  "origin": "IST",
  "destination": "JFK",
  "departureDate": "2026-11-15",
  "flights": [
    {
      "flightNumber": "TK 8",
      "carrier": "TK",
      "departure": "2026-11-15T09:45:00+03:00",
      "arrival":   "2026-11-15T12:35:00-04:00",
      "duration": "10h 50m",
      "equipment": "777",
      "operatingCarrier": "TK"
    },
    …
  ]
}
```

### 2.2 Data Normalisation
| GDS Field | Normalised Property | Type | Notes |
|-----------|---------------------|------|-------|
| `FlightNumber` | `flightNumber` | string | Concatenated carrier + numeric. |
| `DepartureDateTime` | `departure` | ISO‑8601 | Includes UTC offset from origin airport. |
| `ArrivalDateTime` | `arrival` | ISO‑8601 | Includes UTC offset from destination airport. |
| `Equipment` | `equipment` | string | ICAO aircraft type (e.g., `777`). |
| `MarketingCarrier` | `carrier` | string | IATA code for marketing airline. |

## 3. Live Cabin‑Class Availability
### 3.1 Availability Endpoint
```http
GET /gds/v1/flight/availability
Host: api.coretravel.io
Authorization: Bearer <access_token>
Accept: application/json
```

| Query Parameter | Type | Required | Description |
|-----------------|------|----------|-------------|
| `flightKey`     | UUID | Yes | Identifier returned from the schedule call (`flightId`). |
| `cabin`         | enum | No  | One of `ECONOMY`, `PREMECO`, `BUSINESS`, `FIRST`. |
| `date`          | ISO‑8601 | Yes | Date of travel (must match schedule). |

#### Sample Response
```json
{
  "flightId": "9b4e2c1a-8d5f-4a2b-9e33-1d5a6c7b8f90",
  "cabinAvailability": [
    {
      "cabin": "ECONOMY",
      "seatsAvailable": 27,
      "fareBasis": "YVZ",
      "publishedFare": 560.00,
      "currency": "USD"
    },
    {
      "cabin": "BUSINESS",
      "seatsAvailable": 4,
      "fareBasis": "JQK",
      "publishedFare": 2450.00,
      "currency": "USD"
    }
  ]
}
```

### 3.2 Pricing Logic (Inside Core Engine)
1. **Base Fare** – Pulled from GDS fare‑basis record.  
2. **Dynamic Tax Engine** – Calculates airport, fuel, and government taxes per jurisdiction.  
3. **Currency Conversion** – Uses live FX feed (EUR ↔ USD ↔ TRY).  
4. **Markup Layer** – *Zero* – the portal displays the **exact published fare** (no affiliate markup).

## 4. Official CRS Hotel Rate Engine
### 4.1 Hotel Rate Endpoint
```http
GET /crs/v1/hotels/inventory
Host: api.coretravel.io
Authorization: Bearer <access_token>
Accept: application/json
```

| Query Parameter | Type | Required | Description |
|-----------------|------|----------|-------------|
| `cityCode`      | IATA | Yes | City identifier (e.g., `IST`). |
| `checkIn`       | ISO‑8601 (YYYY‑MM‑DD) | Yes | First night. |
| `checkOut`      | ISO‑8601 (YYYY‑MM‑DD) | Yes | Departure night. |
| `guests`        | int | No  | Number of adult guests (default 1). |
| `rooms`         | int | No  | Number of rooms (default 1). |
| `hotelIds`      | CSV | No  | Optional filter to specific properties. |

## 5. White‑Label Direct‑Booking Integration
All UI components are **self‑hosted**; the portal injects the following widgets that query the core endpoints directly.

### 5.1 Flight Search Widget
```
[GDS_FLIGHT_SEARCH_WIDGET]
```

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `containerId` | string | Yes | DOM element ID where the widget will render. |
| `defaultOrigin` | IATA | No | Pre‑filled origin airport (e.g., `IST`). |
| `defaultDestination` | IATA | No | Pre‑filled destination airport. |
| `onSelect` | function | Yes | Callback that receives the chosen `flightId` and cabin object. |
| `theme` | enum (`light`, `dark`) | No | Visual theme to match the host brand. |

**Implementation Sketch (React)**  
```tsx
import { useEffect } from 'react';

declare const GDS_FLIGHT_SEARCH_WIDGET: (options: {
  containerId: string,
  defaultOrigin?: string,
  defaultDestination?: string,
  onSelect: (flight: FlightSelection) => void,
  theme?: 'light' | 'dark'
}) => void;

export const FlightSearch = () => {
  useEffect(() => {
    GDS_FLIGHT_SEARCH_WIDGET({
      containerId: 'flight-widget-root',
      defaultOrigin: 'IST',
      onSelect: (flight) => {
        // Forward to booking flow
        console.log('User selected', flight);
      },
      theme: 'light'
    });
  }, []);

  return <div id="flight-widget-root" />;
};
```

### 5.2 Hotel Inventory Widget
```
[CRS_HOTEL_INVENTORY_WIDGET]
```

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `containerId` | string | Yes | Target DOM element. |
| `cityCode` | IATA | Yes | Destination city (`IST`). |
| `checkIn` | ISO‑8601 | Yes | First night. |
| `checkOut` | ISO‑8601 | Yes | Departure night. |
| `onBook` | function | Yes | Returns selected `hotelId`, `roomTypeId`, and `ratePlanId`. |
| `showFilters` | boolean | No | Enable UI filters (price, category). |
| `theme` | enum | No | Visual appearance. |

**Implementation Sketch (Vue 3)**  
```vue
<template>
  <div id="hotel-widget-root"></div>
</template>

<script setup lang="ts">
declare const CRS_HOTEL_INVENTORY_WIDGET: (opts: {
  containerId: string,
  cityCode: string,
  checkIn: string,
  checkOut: string,
  onBook: (selection: HotelSelection) => void,
  showFilters?: boolean,
  theme?: 'light' | 'dark'
}) => void;

onMounted(() => {
  CRS_HOTEL_INVENTORY_WIDGET({
    containerId: 'hotel-widget-root',
    cityCode: 'IST',
    checkIn: '2026-11-15',
    checkOut: '2026-11-20',
    onBook: (selection) => {
      console.log('Hotel selected', selection);
    },
    showFilters: true,
    theme: 'dark'
  });
});
</script>
```

> **Note:** Both widgets are **self‑contained**; they do **not** call any affiliate APIs, guaranteeing a 0 % third‑party dependency.

## 6. Security & Compliance
| Aspect | Implementation |
|--------|----------------|
| **Authentication** | OAuth 2.0 Client‑Credentials flow. Tokens scoped to `flight.read`, `flight.book`, `hotel.read`, `hotel.book`. |
| **Transport** | Enforced TLS 1.3 with forward‑secrecy cipher suites. |
| **PCI‑DSS** | Card data never traverses the Core Engine – tokenised payment payloads are forwarded to the merchant’s own PSP. |
| **GDPR / CCPA** | All PII is encrypted at rest (AES‑256) and masked in logs. Users may request data erasure via `/privacy/v1/requests`. |
| **Rate‑Limiting** | 200 req/s per client ID with burst‑cap 500. Exceeded requests receive `429 Too Many Requests`. |
| **Audit Trail** | Every mutation (`booking`, `cancellation`) writes an immutable entry to an append‑only log (Amazon QLDB / Azure Confidential Ledger). |
