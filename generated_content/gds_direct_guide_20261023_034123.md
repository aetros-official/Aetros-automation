## 2. Live Flight Data – Direct Airline Schedules
| Parameter | Description | Recommended Retrieval Method |
|-----------|-------------|------------------------------|
| **Carrier Code** | IATA airline identifier (e.g., TK for Turkish Airlines) | `AirlineInfoRequest` |
| **Flight Number** | Unique flight identifier (e.g., TK 1852) | `FlightScheduleRQ` |
| **Departure/Arrival Airports** | IATA codes (IST, LHR, DXB…) | `AirScheduleRQ` |
| **Operating Dates** | Calendar days the flight operates (including seasonal patterns) | `FlightLegsRQ` |
| **Time‑zone Normalisation** | Store UTC and convert to local via `TZDB` | Apply `Offset` from GDS response |
| **Equipment Type** | Aircraft model (e.g., A320, B787) | `AircraftInfoRQ` |
| **Connection Rules** | Minimum/Maximum layover times, prohibited connections | `ConnectionInfoRQ` |

**Key Technical Note**  
- Use **PCC (Pseudo City Code)** credentials dedicated to the portal; never share with affiliate partners.  
- Set **`IncludeLegDetails=Y`** to retrieve full segment breakdown for multi‑city itineraries.

## 3. Cabin Class Availability & Fare Construction
| Cabin Code | Meaning | Typical Fare Basis Prefix | GDS Attribute |
|-----------|---------|---------------------------|----------------|
| **Y** | Economy (full‑fare) | `Y`, `YB`, `YA` | `CabinClass=Y` |
| **M** | Economy (discounted) | `M`, `MN` | `CabinClass=M` |
| **W** | Premium Economy | `W`, `WP` | `CabinClass=W` |
| **J** | Business | `J`, `JB` | `CabinClass=J` |
| **C** | Business (full‑fare) | `C`, `CB` | `CabinClass=C` |
| **F** | First | `F`, `FA` | `CabinClass=F` |

### Fare Construction Steps
1. **Fare Quote Request** – `AirShoppingRS` with `CabinClass` filters.  
2. **Tax & Surcharge Aggregation** – Pull tax breakdown (`TaxInfo`) from GDS; apply **airport‑specific** and **carrier‑specific** surcharges.  
3. **Currency Normalisation** – Convert using **real‑time FX rates** (e.g., from Open Exchange Rates API) only if the portal supports multi‑currency display; store base fare in **USD** for accounting.  
4. **Dynamic Pricing Rules** – Implement **Rule Engine** that respects:
   - **Advance Purchase** (e.g., >21 days → 5 % discount)
   - **Length‑of‑Stay** (LOS) constraints
   - **Cabin‑Upgrade Eligibility** (based on fare class hierarchy)  

### Example Fare Rule (Pseudo‑code)
```python
def calculate_final_fare(base_fare, cabin_code, days_to_departure):
    discount = 0
    if cabin_code in ['Y','M'] and days_to_departure >= 21:
        discount = 0.05   # 5% early‑bird for economy
    elif cabin_code in ['J','C'] and days_to_departure >= 14:
        discount = 0.03   # 3% early‑bird for business
    return round(base_fare * (1 - discount), 2)
```

## 4. Live Hotel CRS Rates – Property‑Level Inventory
| Data Element | Source | Retrieval Method |
|--------------|--------|------------------|
| **Hotel ID** | CRS Property Code (e.g., `HOTEL12345`) | `HotelPropertyInfoRQ` |
| **Room Type Code** | CRS Rate Plan ID (e.g., `DLX_STD`) | `RatePlanInfoRQ` |
| **Availability** | Real‑time inventory per night | `HotelAvailabilityRQ` |
| **Rate per Night** | Published net rate (including taxes) | `HotelRateRQ` |
| **Board Basis** | `RO` (room only), `BB` (bed‑&‑breakfast), `HB` (half‑board) | `BoardType` attribute |
| **Cancellation Policy** | `CXLPolicy` object with deadline & penalty | `PolicyInfoRQ` |

### Sample Hotel Rate Request (XML)
```xml

   xmlns="http://www.opentravel.org/OTA/2003/05">

  </POS>
```

## 5. White‑Label Integration Points  

### 5.1 Flight Booking Widget  
Insert the following placeholder **exactly where the UI component should render**. The portal’s front‑end framework will replace the tag with a fully‑featured, GDS‑powered flight search & seat‑selection UI.

```html
<!-- BEGIN GDS Flight Search & Booking -->
[GDS_FLIGHT_SEARCH_WIDGET]
<!-- END GDS Flight Search & Booking -->
```

**Widget Requirements**
| Requirement | Details |
|-------------|---------|
| **API Endpoint** | `https://api.amadeus.com/v2/shopping/flight-offers` (or Sabre equivalent) |
| **Auth** | OAuth2 client‑credentials – store token in server‑side cache (TTL 30 min). |
| **Parameters** | Origin, Destination, Departure/Return dates, Passenger count, Cabin class filters. |
| **Output** | JSON payload → UI renders flight list, fare breakdown, seat map (via `SeatMapRQ`). |
| **Booking Confirmation** | POST to `AirBookingCreateRQ` → receive **PNR** and **Ticket Numbers**. |
| **Compliance** | Capture **GDS‑issued TKT‑Number**, **Ticketing Time Limits**, **Fare Rules** for post‑sale audit. |

### 5.2 Hotel Inventory Widget  
Place this tag where the property‑level hotel search & booking UI should appear.

```html
<!-- BEGIN CRS Hotel Inventory & Booking -->
[CRS_HOTEL_INVENTORY_WIDGET]
<!-- END CRS Hotel Inventory & Booking -->
```

**Widget Requirements**
| Requirement | Details |
|-------------|---------|
| **API Endpoint** | `https://api.amadeus.com/v2/hotel-offers` (or Sabre SynXis endpoint). |
| **Auth** | Same OAuth2 token as flight widget – shared token store. |
| **Parameters** | Destination (city/airport code), check‑in/out dates, room count, occupancy, rate‑plan filters. |
| **Output** | JSON/OTA XML → UI displays property images, room types, live per‑night rates, cancellation policies. |
| **Booking Confirmation** | POST to `HotelBookingCreateRQ` → receive **Booking Confirmation Number** and **Hotel Voucher**. |
| **Compliance** | Store **CRS‑generated RatePlanID**, **Rate Basis**, and **Tax breakdown** for reconciliation. |

## 6. Security, Rate Limiting & Compliance  

| Aspect | Recommended Implementation |
|--------|----------------------------|
| **Transport Security** | Enforce TLS 1.3 for all outbound GDS/CRS calls. |
| **Authentication** | Use **OAuth2 client‑credentials**; rotate client secret every 90 days. |
| **IP Whitelisting** | Restrict API calls to GDS/CRS provider‑issued IP ranges. |
| **Rate Limiting** | Implement a **token bucket** per PCC (e.g., 5 req/s, burst up to 20) to avoid throttling. |
| **PCI‑DSS** | Never store raw credit‑card data; redirect to carrier/CRS payment gateways using **Hosted Payment Pages**. |
| **GDPR / Data Retention** | Keep personal data ≤ 30 days unless a booking is confirmed; purge otherwise. |
| **Audit Trail** | Log request/response IDs, timestamps, and user session IDs for all GDS/CRS calls. |
