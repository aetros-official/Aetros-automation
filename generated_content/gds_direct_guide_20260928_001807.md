## 1. Executive Summary  

This guide provides **authoritative, production‑grade instructions** for building a **white‑label travel portal** that draws **exclusively** from **Amadeus / Sabre Core Engine** (air) and **Central Reservation Systems (CRS)** (hotel) for Istanbul (IST) market data.  

* **Zero reliance on affiliate networks** – every flight, cabin‑class availability, and hotel rate originates from live GDS/CRS feeds.  
* **Real‑time, transactional‑grade data** – guaranteed by the direct socket/HTTPS API connections to the carrier and hotel CRS.  
* **Plug‑and‑play UI placeholders** – `[GDS_FLIGHT_SEARCH_WIDGET]` and `[CRS_HOTEL_INVENTORY_WIDGET]` – can be swapped for any front‑end framework (React, Angular, Vue, native mobile) without altering the back‑end logic.

## 2. Core Data Sources  

| Source | Protocol | Endpoint (example) | Data Scope |
|--------|----------|--------------------|-----------|
| **Amadeus / Sabre Core Engine** | TCP/HTTPS (TLS 1.3) | `https://api.amadeus.com/v2/shopping/flight-offers` | Live carrier schedules, seat maps, fare families, cabin‑class inventory, fare rules. |
| **CRS Hotel Engine** (e.g., **Sabre SynXis**, **Amadeus Hotel Connect**) | HTTPS (REST) | `https://api.sabre.com/v2/hotels/availability` | Real‑time property inventory, room type codes, rate plans, tax & fee breakdowns. |
| **Currency & Tax Service** | HTTPS | `https://api.enterprise.com/v1/finance/tax` | Dynamic tax, surcharge & currency conversion per jurisdiction. |

> **Note:** All endpoints require **OAuth 2.0 client‑credentials** tokens that are **generated per‑session** and scoped to **`flight:search hotel:availability`** only. No broader scopes (e.g., marketing) are permitted.

## 3. Direct Airline Schedule & Cabin‑Class Engine  

### 3.1 Data Model  

| Field | Type | Description |
|-------|------|-------------|
| `flightNumber` | string | Carrier code + numeric flight number (e.g., `TK2024`). |
| `departureAirport` | IATA | Origin airport (e.g., `IST`). |
| `arrivalAirport` | IATA | Destination airport. |
| `departureTimeUTC` | ISO‑8601 | Exact UTC departure timestamp. |
| `arrivalTimeUTC` | ISO‑8601 | Exact UTC arrival timestamp. |
| `cabinClass` | enum (`Y`, `W`, `J`, `F`, `P`, `S`) | Economy, Premium Economy, Business, First, etc. |
| `availableSeats` | integer | Real‑time seat count after allocation rules. |
| `fareBasisCode` | string | GDS‑issued fare family identifier. |
| `price` | decimal | Net fare in the request currency (excl. taxes). |
| `taxes` | array | Detailed tax objects (type, amount). |
| `priceTotal` | decimal | `price + taxes`. |
| `bookingClass` | string | Airline revenue class (e.g., `Y`, `M`, `K`). |

### 3.2 Query Pattern  

```http
POST https://api.amadeus.com/v2/shopping/flight-offers
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "originLocationCode": "IST",
  "destinationLocationCode": "LHR",
  "departureDate": "2026-12-01",
  "adults": 1,
  "travelClass": "ECONOMY",          // maps to cabinClass = Y
  "max": 200,                         // max results
  "includeTicketing": false,
  "currencyCode": "USD"
}
```

**Key flags for “direct‑only” mode**  

| Parameter | Value | Reason |
|-----------|-------|--------|
| `includeAllotments` | `false` | Prevents allocation of affiliate‑controlled inventory. |
| `source` | `GDS` | Forces GDS‑originated offers only. |
| `excludeAffiliates` | `true` | Filters out any offers flagged as affiliate‑derived. |

### 3.3 Cabin‑Class Availability Logic  

1. **Seat‑map pull** – For each flight returned, issue a **SeatMap API** call (`/v2/shopping/flight-offers/seatmap`) to retrieve real‑time cabin‑class breakdown.  
2. **Business Rules** – Apply the portal’s **Cabin‑Class Policy Engine** (e.g., block “restricted” fare families for corporate accounts).  
3. **Cache Invalidation** – TTL = **30 seconds**. After TTL, re‑query the GDS to guarantee up‑to‑the‑minute accuracy.

## 4. Live Hotel CRS Rate Engine  

### 4.1 Data Model  

| Field | Type | Description |
|-------|------|-------------|
| `propertyId` | string | CRS‑generated unique identifier. |
| `hotelName` | string | Official hotel name. |
| `roomTypeCode` | string | CRS‑defined room type (e.g., `DBL_STD`). |
| `ratePlanCode` | string | Rate plan (e.g., `NONREFUNDABLE`). |
| `availableRooms` | integer | Real‑time inventory count. |
| `baseRate` | decimal | Net room price before taxes/fees. |
| `taxes` | array | Tax objects (city, VAT, tourism tax). |
| `priceTotal` | decimal | `baseRate + taxes`. |
| `cancellationPolicy` | string | Human‑readable policy (e.g., “Free cancellation until 18 h prior”). |
| `amenities` | array | List of property amenities (pool, Wi‑Fi, etc.). |
| `roomDescription` | string | Marketing copy supplied by CRS. |

### 4.2 Query Pattern  

```http
POST https://api.sabre.com/v2/hotels/availability
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "cityCode": "IST",
  "checkInDate": "2026-12-10",
  "checkOutDate": "2026-12-15",
  "roomQuantity": 1,
  "adults": 2,
  "children": 0,
  "currencyCode": "EUR",
  "includeRatePlans": true,
  "excludeAffiliates": true
}
```

**Important flags**  

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| `source` | `CRS` | Guarantees direct CRS data. |
| `excludeAffiliates` | `true` | Removes any syndicated or OTA‑derived rates. |
| `ratePlanFilter` | `["NONREFUNDABLE","REFUNDABLE"]` | Allows business logic to present only approved plans. |

### 4.3 Rate Normalisation  

1. **Tax Aggregation** – Pull tax breakdown from CRS and **merge** with the **Enterprise Tax Service** for jurisdiction‑specific compliance.  
2. **Currency Conversion** – Use the **Enterprise FX Service** (real‑time mid‑market rates) to convert to the user‑selected currency **before** display.  
3. **Price Rounding** – Round to **two decimal places** using **banker’s rounding** to avoid cumulative rounding errors across multi‑night stays.

## 5. White‑Label Booking Integration Blueprint  

> **All UI components are pure placeholders.** Replace them with your front‑end framework’s component wrappers, but **do not alter** the underlying API contracts.

### 5.1 Flight Search Widget  

```
[GDS_FLIGHT_SEARCH_WIDGET]
```

**Required Props (JSON)**  

| Prop | Type | Description |
|------|------|-------------|
| `origin` | string | IATA code (e.g., `IST`). |
| `destination` | string | IATA code. |
| `departureDate` | string (YYYY‑MM‑DD) | Travel date. |
| `returnDate` | string (optional) | For round‑trip. |
| `adults` | integer | Adult passenger count. |
| `cabinClass` | string (`Y`, `W`, `J`, `F`) | Desired cabin. |
| `currency` | string (ISO‑4217) | Display currency. |
| `onSelect` | callback | Returns the **flightOfferId** and **priceTotal** to the back‑end. |

**Behavior**  

* Calls the **Flight Search Service** (Section 3) **on mount**.  
* Shows a **progress spinner** until the first response is received (≤ 2 s SLA).  
* Renders **price‑sorted** results; user can filter by **departure time** and **cabin class**.  
* When a flight is selected, `onSelect` triggers a **pre‑booking hold** (see § 6).  

### 5.2 Hotel Inventory Widget  

```
[CRS_HOTEL_INVENTORY_WIDGET]
```

**Required Props (JSON)**  

| Prop | Type | Description |
|------|------|-------------|
| `cityCode` | string | IATA city (e.g., `IST`). |
| `checkIn` | string (YYYY‑MM‑DD) | Arrival date. |
| `checkOut` | string (YYYY‑MM‑DD) | Departure date. |
| `rooms` | integer | Number of rooms. |
| `adults` | integer | Adults per room. |
| `currency` | string | Display currency. |
| `onSelect` | callback | Returns **propertyId**, **roomTypeCode**, **ratePlanCode**, **priceTotal**. |

**Behavior**  

* Issues a **single CRS availability request** (Section 4) per widget load.  
* Implements **infinite scroll** with **page‑size = 50** to meet UI performance standards.  
* Shows **live inventory badge** (`availableRooms > 0 ? “Available” : “Sold Out”`).  
* Supports **rate‑plan filter toggle** (e.g., “Non‑refundable only”).

## 6. Booking Flow & Transactional Guarantees  

1. **Search → Select** – Widget returns a **selection token** (`flightOfferId` / `hotelRoomToken`).  
2. **Hold (Pre‑authorization)** –  
   * **Flight**: POST `/v2/shopping/flight-offers/{flightOfferId}/seat-reservation` (holds seats for **15 min**).  
   * **Hotel**: POST `/v2/hotels/reservations/hold` (holds rooms for **30 min**).  
3. **Customer Details Capture** – Securely store PII in **PCI‑DSS**‑compliant vault.  
4. **Confirm & Issue Ticket / Booking Confirmation** –  
   * **Flight**: `POST /v2/booking/flight-orders` with the held reservation token.  
   * **Hotel**: `POST /v2/hotels/reservations` with the hold token.  
5. **Atomicity (Optional)** – For combined flight‑hotel packages, use a **two‑phase commit** wrapper that rolls back the hold on either side if the other fails.  

**SLA**  

| Step | Max Latency | Success Rate |
|------|-------------|--------------|
| Search API response | 2 s | 99.7 % |
| Hold request | 1 s | 99.9 % |
| Confirmation | 3 s | 99.5 % |
