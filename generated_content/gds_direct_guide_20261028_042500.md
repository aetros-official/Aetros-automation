> **Version**: 1.0.0 • **Last Updated**: 2026‑10‑28  
> **Audience**: Backend developers, product managers, and data‑science teams building a white‑label travel booking platform that talks *directly* to GDS/CRS systems (Amadeus & Sabre).

## 1️⃣ Overview  

| Feature | Source | Live Data | Notes |
|---------|--------|-----------|-------|
| **Flight Schedules & Seat Availability** | **Amadeus / Sabre Core Engine** | ✔️ | Real‑time seat‑level inventory and pricing |
| **Cabin Class Availability & Pricing** | **Amadeus / Sabre Core Engine** | ✔️ | Multi‑class (E, B, F, etc.) with dynamic fare rules |
| **Hotel CRS Rates** | **Amadeus / Sabre CRS** | ✔️ | Fully compliant with Hotel Rate Codes, ADR, and OTB |

> **Goal:** Enable a *single‑click* direct booking experience while keeping *data ownership* fully in-house. All pricing, inventory, and booking flows are routed through your own backend, respecting the carrier’s and hotel’s rate‑control rules.

## 2️⃣ Technical Architecture

```
┌─────────────────────┐
│  White‑Label Frontend│   ←  UI widgets
└─────▲───────▲───────┘
      │       │
      │[REST/GraphQL]  ←  Custom API layer
      │
┌─────▼───────▼───────┐
│  Service Layer      │   ←  Auth, rate‑limit, caching
└─────▲───────▲───────┘
      │       │
      │[XML/JSON]  ←  GDS/CRS adapters
      │
┌─────▼───────▼───────┐
│  Amadeus / Sabre    │   ←  Direct GDS/CRS connections
└─────────────────────┘
```

1. **Front‑end widgets** consume JSON responses from your own API.  
2. **Service Layer** enforces *carrier rate‑control*, *session persistence*, and *security* (PCI‑DSS, GDPR).  
3. **Adapters** translate your REST/GraphQL calls into the proprietary PNR/OTA XML of each GDS.  
4. **GDS / CRS** are the *single source of truth*; all data is 100 % live.

> **Tip:** Use *Amadeus Flight Offers API* (FOTA) or *Sabre Flight Offer* endpoint for real‑time seat pricing. For hotels, use *Amadeus Hotel Offers* or *Sabre Hotel Availability* APIs.

## 3️⃣ Direct Airline Schedules & Seat Availability

### 3.1. Flight Search

| Parameter | Type | Description | Example |
|-----------|------|-------------|---------|
| `origin` | `IATA code` | Departure airport | `IST` |
| `destination` | `IATA code` | Arrival airport | `LHR` |
| `departureDate` | `YYYY-MM-DD` | Travel date | `2026-12-25` |
| `returnDate` | `YYYY-MM-DD` | For round‑trip | `2026-12-30` |

### 3.2. Real‑Time Seat Availability

- **`GET /flightOffers/search`** → *search flight offers*  
- **`GET /flightOffers/{offerId}/availability`** → *seat‑level availability*  
  - Returns *segment‑specific* seat counts, *cabin class* pricing, and *fare rules*.

**Note:**  
- **Seat‑level booking** requires *PNR creation* on the GDS.  
- Your **backend** must store the *booking token* (e.g., `GDS-PNR-ID`) for later confirmation or cancellation.

## 4️⃣ Hotel CRS Rates

### 4.1. Hotel Search

| Parameter | Type | Description | Example |
|-----------|------|-------------|---------|
| `cityCode` | `IATA` | City or hotel code | `IST` |
| `checkInDate` | `YYYY-MM-DD` | Check‑in | `2026-12-20` |
| `checkOutDate` | `YYYY-MM-DD` | Check‑out | `2026-12-25` |
| `guests` | `int` | Adults / children | `2` |

### 4.2. Rate Rules & OTB

- **`OTB`** – *Open Trading Buffer*: dynamic price changes allowed within a 24‑hour window.  
- **`CRS_RATES_ENDPOINT`** must support *price‑flexibility* queries; pass `OTB=true` to fetch live OTB rates.  
- All **taxes, fees, and surcharges** are returned per rate – never hard‑code them.

## 5️⃣ White‑Label Direct Booking Integration

### 5.1. Flight Widget – [GDS_FLIGHT_SEARCH_WIDGET]

```html
<!-- Insert this widget into your booking page -->
<div id="flight-search-widget">
  <GDS_FLIGHT_SEARCH_WIDGET
    apiEndpoint="https://api.yourdomain.com/gds/flights"
    clientId="YOUR_CLIENT_ID"
    clientSecret="YOUR_CLIENT_SECRET"
    locale="en_US"
    currency="EUR"
  />
</div>
```

> **Behind the Scenes:**  
> 1. Widget sends a **search request** to your `/gds/flights` endpoint.  
> 2. Your backend calls the Amadeus/Sabre flight‑offer API.  
> 3. Widget displays offers in an *interactive grid* with **“Book Now”** buttons.  
> 4. On click, widget calls `/gds/flights/booking` which initiates a **PNR** and returns a **booking confirmation**.

### 5.2. Hotel Widget – [CRS_HOTEL_INVENTORY_WIDGET]

```html
<!-- Insert this widget into your hotel search page -->
<div id="hotel-search-widget">
  <CRS_HOTEL_INVENTORY_WIDGET
    apiEndpoint="https://api.yourdomain.com/crs/hotels"
    clientId="YOUR_CLIENT_ID"
    clientSecret="YOUR_CLIENT_SECRET"
    locale="en_US"
    currency="EUR"
  />
</div>
```

> **Behind the Scenes:**  
> 1. Widget sends a **hotel search request** to `/crs/hotels`.  
> 2. Backend queries the Amadeus/Sabre Hotel Offers API.  
> 3. Widget renders results with **price breakdown** (room + taxes).  
> 4. **“Reserve”** button triggers a reservation call to `/crs/hotels/booking`, creating a **CRS reservation** and delivering the final confirmation.

### 5.3. Authentication & Security

| Feature | Requirement | Implementation |
|---------|-------------|----------------|
| **OAuth 2.0** | GDS credentials | `client_credentials` flow – store `access_token` with short lifetime |
| **PCI‑DSS** | Credit card data | Tokenise on the front‑end; only store minimal data on backend |
| **GDPR** | Personal data | Store only necessary passenger/hotel details; secure PII |

### 5.4. Error Handling & Retries

```json
{
  "error": {
    "code": "GDS_RATE_LIMIT_EXCEEDED",
    "message": "You have exceeded the allowed number of requests. Please retry after 30s."
  }
}
```

- **Back‑off strategy**: exponential back‑off, maximum 5 retries.  
- **Fallback**: display a friendly message – “Please try again in a minute.”

## 7️⃣ FAQ

| Question | Answer |
|----------|--------|
| **Do we need an affiliate partnership?** | No. All inventory, pricing, and booking flows are *direct* from GDS/CRS. |
| **What about data latency?** | GDS APIs are real‑time. Use WebSockets or server‑sent events for push updates on seat availability. |
| **Can we use the same widget for multiple GDS?** | Yes – the widget is agnostic. Your backend can route to Amadeus or Sabre depending on the *carrier* or *market*. |
| **Is there a cost?** | GDS/CRS connectivity incurs *per‑request* fees. Budget accordingly. |

## 8️⃣ Quick Start Checklist

1. **Obtain GDS/CRS credentials** (client ID / secret) from Amadeus and Sabre.  
2. **Spin up** a secure API gateway and set up **OAuth 2.0**.  
3. **Implement adapters** for:  
   - `GET /gds/flights/search` → *Flight Offers*  
   - `POST /gds/flights/booking` → *Create PNR*  
   - `GET /crs/hotels/search` → *Hotel Offers*  
   - `POST /crs/hotels/booking` → *Create Reservation*  
4. **Deploy widgets** ([GDS_FLIGHT_SEARCH_WIDGET] & [CRS_HOTEL_INVENTORY_WIDGET]) into your UI.  
5. **Test** with a sandbox environment (Amadeus/ Sabre sandbox).  
6. **Go live** – monitor **rate limits**, **error rates**, and **conversion metrics**.
