## 1. Executive Summary
The **Enterprise Travel Portal** delivers **100 % direct** access to airline inventory and hotel pricing via the **Amadeus/Sabre Core Engines**. All flight and hotel data are pulled **live** from carrier schedules, cabin‑class availability streams, and the **CRS (Central Reservation System)** for Istanbul (IST) properties—eliminating any reliance on third‑party affiliate networks.

Key business outcomes:

| KPI | Target | Rationale |
|-----|--------|-----------|
| **Conversion Rate** | ≥ 7 % | Real‑time, price‑guaranteed inventory removes friction. |
| **Average Booking Value** | +12 % YoY | Direct fare bundles and dynamic fare‑class upsell. |
| **System Uptime** | 99.95 % | Multi‑region active‑active GDS/CRS connectivity. |
| **Latency (Flight/Hotel search)** | ≤ 250 ms | Edge caching + parallelized request pipelines. |

### 3.1 Technical Access Details
| Parameter | Value |
|-----------|-------|
| **Endpoint** | `https://api.amadeus.com/v2/shopping/flight‑offers` |
| **Auth** | OAuth 2.0 Client Credentials (JWT, 1 h expiry) |
| **Transport** | TLS 1.3, mutual TLS optional for carrier‑level contracts |
| **Payload** | JSON – includes `segmentId`, `departureTime`, `arrivalTime`, `flightNumber`, `aircraftCode`, `marketingCarrier`, `operatingCarrier` |
| **Rate‑Limit** | 5 000 req/min per client‑ID (burst 2 000) |

> **Note:** All schedule data is **carrier‑certified**; no markup or “virtual” legs are injected.  

### 3.2 Embedding the Flight Search UI


*The widget automatically renders a responsive, multi‑city search box that queries the **Flight Service** with the parameters defined above. No affiliate URLs are ever generated.*

## 4. Live Cabin Class Availability  

| Cabin | Code | Real‑Time Feed | Refresh Cadence |
|-------|------|----------------|-----------------|
| Economy | Y | **SeatMap API** (Sabre) | 5 s |
| Premium Economy | W | **SeatMap API** (Amadeus) | 5 s |
| Business | C | **SeatMap API** (Sabre) | 3 s |
| First | F | **SeatMap API** (Amadeus) | 3 s |

### 4.1 Data Pipeline
1. **Kafka Topic:** `gds.cabin.availability` – each message contains `flightKey`, `cabinCode`, `availableSeats`, `fareBasis`, `price`.  
2. **Consumer:** `CabinAvailabilityService` updates an in‑memory LRU cache (max 2 M entries).  
3. **API Exposure:** `GET /flights/{flightKey}/cabin/{cabinCode}` returns the latest seat count and fare‑basis.

### 4.2 Pricing Logic
* **Dynamic Pricing Engine** applies **fare‑class rules**, **inventory‑driven elasticity**, and **ancillary bundles** (e.g., extra baggage, seat selection).  
* **Price Guarantee:** The moment a fare is displayed, a **2‑minute hold** is placed at the GDS level to lock the quoted amount.

## 6. White‑Label Integration Blueprint  

| Integration Layer | Responsibility | Technical Artifact |
|-------------------|----------------|--------------------|
| **Presentation** | Render flight & hotel widgets, maintain brand consistency | `[GDS_FLIGHT_SEARCH_WIDGET]`, `[CRS_HOTEL_INVENTORY_WIDGET]` |
| **API Gateway** | Centralized auth, throttling, request routing | Kong/Envoy config snippets |
| **Flight Service** | Query Amadeus/Sabre, aggregate cabin class, apply fare rules | `flight-service.jar` (Java 21) |
| **Hotel Service** | Query CRS, map property IDs to internal catalog | `hotel-service.py` (FastAPI) |
| **Booking Orchestration** | Atomic transaction across flight & hotel legs, generate PNR & reservation code | `orchestrator.go` |
| **Persistence** | Immutable audit trail (flight‑PNR, hotel‑confirmation) | PostgreSQL + Append‑Only Table |
| **Cache** | Redis‑Cluster (TTL 30 s for flight, 60 s for hotel) | `redis.conf` |

```json
POST /api/v1/flights/search

  "origin": "IST",
  "destination": "JFK",
  "departureDate": "2027-04-15",
```

> **Zero Affiliate Dependency** – All responses contain **only** the native GDS/CRS identifiers and pricing. No third‑party IDs, tracking pixels, or external referral URLs are introduced.

## 7. Security & Compliance  

| Control | Implementation |
|---------|----------------|
| **Authentication** | OAuth 2.0 (client‑credentials) + JWT signing with RSA‑256. Refresh tokens rotated every 12 h. |
| **Transport Encryption** | TLS 1.3 mandatory; Perfect Forward Secrecy (ECDHE‑P‑256). |
| **PCI DSS** | Card data never touches the portal; tokenization occurs in the payment gateway only. |
| **GDPR / Data Residency** | All PII stored in EU‑region PostgreSQL with encrypted columns (AES‑256). |
| **Audit Logging** | Immutable CloudTrail‑style logs for every GDS/CRS request (request‑ID, timestamp, hash). |
| **Rate‑Limiting** | Token‑bucket per client‑ID; hard‑cap prevents abuse and protects GDS/CRS SLAs. |

## 8. Performance, Caching & Rate‑Limiting  

| Metric | Target | Mechanism |
|--------|--------|-----------|
| **Search Latency (flight)** | ≤ 250 ms | Parallel calls to Amadeus & Sabre; in‑memory seat‑map cache (TTL 5 s). |
| **Search Latency (hotel)** | ≤ 300 ms | Redis‑Cluster with geo‑partitioning; pre‑warm top‑100 Istanbul properties. |
| **Cache Invalidation** | Event‑driven (Kafka) + TTL fallback. |
| **Burst Protection** | Adaptive token bucket; auto‑scale API Gateway pods. |
| **Cold‑Start Mitigation** | Warm‑up cron jobs every 5 min for popular routes (IST‑LHR, IST‑DXB). |
