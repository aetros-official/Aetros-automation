## 1. Introduction  

The enterprise travel portal must provide **real‑time, end‑to‑end booking** for flights and hotels while presenting a unified, white‑label experience to corporate clients. The portal must:

1. Pull **Direct Carrier Schedules** (flight legs, times, frequencies).
2. Expose **Live Cabin Class Availability** (economy, premium, business, first).
3. Show **Official CRS Hotel Rates** for the requested market (here, Istanbul – IST).
4. Allow **instant seat/hotel reservations** through embedded widgets.

This guide gives a step‑by‑step framework to build a robust, high‑conversion booking engine directly connected to GDS/CRS.

## 2. Data Sources & Schema  

| Source | Vendor | Data Type | Frequency | Primary Key | Key Notes |
|--------|--------|-----------|-----------|------------|-----------|
| **Amadeus GDS** | Flight schedules, cabin availability | `FlightSchedule` | 1‑hour incremental update | `FlightNumber+Date+Origin+Dest` | Real‑time `FlightAvailability` API |
| **Sabre GDS** | Flight schedules, seat map | `SeatMap` | 15‑min refresh | `FlightKey` | `CabinClass` structure |
| **Hotel CRS (e.g., IATA‑conform)** | Rate plans, inventory | `HotelRatePlan` | 5‑min | `HotelCode+RateCode+Date` | Includes `RoomType`, `BedConfiguration` |

> **Schema Highlights**  
> * `FlightSchedule` fields: `FlightNumber`, `DepartureTime`, `ArrivalTime`, `Duration`, `OperatingAirline`, `AircraftType`.  
> * `CabinAvailability`: `CabinClass`, `SeatsLeft`, `FareBasisCode`, `EffectiveDate`, `ExpDate`.  
> * `HotelRatePlan`: `HotelCode`, `RateCode`, `Price`, `Currency`, `Availability`, `TaxBreakdown`.

All APIs use **REST/JSON** for portability. Underlying data is stored in a **dedicated PostgreSQL** instance with a `schema_gds_crs` namespace. Real‑time streams feed into the `gds_live` topic via Apache Kafka.

## 3. Flight Search & Seat Availability  

### 3.1. Core Search Flow  

1. **Search Request** (`GET /api/flight/search`)  
   - Parameters: `origin`, `destination`, `date`, `cabinPreference`, `segments`, `passengerCount`.  
2. **Query Engine**  
   - Pulls schedules from `flight_schedule`.  
   - Joins with `cabin_availability` for seat counts.  
   - Applies fare calculation rules (e.g., taxes, surcharges).  
3. **Result Set**  
   - Returns array of `FlightOption` objects.

### 3.2. API Schema (JSON)  

```json
{
  "searchId": "uuid",
  "timestamp": "2026-10-04T12:00:00Z",
  "origin": "IST",
  "destination": "LHR",
  "date": "2026-12-15",
  "cabinClasses": [
    {
      "cabin": "Economy",
      "availableSeats": 12,
      "fareBasis": "Y",
      "price": 115.00,
      "currency": "EUR"
    },
    {
      "cabin": "Business",
      "availableSeats": 3,
      "fareBasis": "J",
      "price": 450.00,
      "currency": "EUR"
    }
  ],
  "flightSegments": [
    {
      "flightNumber": "TK123",
      "airline": "Turkish Airlines",
      "departure": "2026-12-15T08:00:00",
      "arrival": "2026-12-15T12:00:00",
      "duration": "4h 0m"
    }
  ]
}
```

### 3.3. Seat Map & Booking

- **Seat Map**: `GET /api/flight/seatmap/{flightKey}` returns a `SeatMap` object with seat coordinates and class segmentation.  
- **Reservation**: `POST /api/flight/book` sends selected `flightKey`, `seatNumbers`, `passengerInfo` → returns `bookingReference` (PNR).

### 3.4. Widget Integration


> **Implementation Tip**

## 4. Hotel CRS Inventory & Rates  

### 4.1. Inventory Retrieval  

1. **Search Request** (`GET /api/hotel/search`)  
   - Parameters: `location=IST`, `checkIn`, `checkOut`, `rooms`, `adults`, `children`.  
2. **Query Engine**  
   - Pulls `HotelRatePlan` for the date range.  
   - Filters by `Availability > 0`.  
   - Calculates `TotalPrice` = `RoomRate` × `Nights` + `Taxes`.  

### 4.2. API Schema (JSON)  

```json
{
  "searchId": "uuid",
  "hotelResults": [
    {
      "hotelCode": "HS123",
      "hotelName": "Hilton Istanbul",
      "address": "Istiklal Avenue, Istanbul",
      "rating": 4.5,
      "roomTypes": [
        {
          "roomCode": "Deluxe",
          "description": "Deluxe Twin Room",
          "beds": "2 King",
          "availability": 5,
          "pricePerNight": 99.99,
          "currency": "EUR",
          "taxes": {
            "VAT": 20.0,
            "Service": 5.0
          }
        }
      ]
    }
  ]
}
```

### 4.3. Booking Flow  

- **Reservation**: `POST /api/hotel/book` → requires `hotelCode`, `roomCode`, `bookingDates`, `guestInfo`. Returns `bookingReference` and a QR code for check‑in.

### 4.4. Widget Integration  

```markdown

```

> **Widget Design**

## 6. Fare Analysis & Conversion Optimization  

### 6.1. Key Metrics  

- **Occupancy Rate** – % of seats/hotels filled at a given price.  
- **Yield** – Revenue / Available seat inventory.  
- **Break‑Even Price** – Minimum fare to cover operational costs.  

### 6.2. Analysis Pipeline  

1. **Data Ingest** – Real‑time Kafka streams push `FlightAvailability` and `HotelRatePlan` into a Snowflake data warehouse.  
2. **Processing** – Use dbt to model `flight_fares`, `hotel_fares`.  
3. **BI Layer** – PowerBI/Looker dashboards for corporate executives.  

### 6.3. Conversion Tactics  

| Tactic | Description | Technical Implementation |
|--------|-------------|--------------------------|
| **Dynamic Pricing** | Adjust fares based on demand and time to departure. | Use a rule engine that pulls `SeatsLeft` and `HotelAvailability` to compute `priceMultiplier`. |
| **Bundle Discounts** | Offer flight + hotel packages. | Implement a composite API (`/api/bundle`) that aggregates both datasets and applies a discount logic. |
| **Seat Class Upsell** | Promote higher cabin classes with limited seats. | Highlight `availableSeats` and a “Book Now” CTA for premium cabins. |

## 7. Security, Compliance & Data Governance  

| Requirement | Detail | Implementation |
|-------------|--------|----------------|
| **PCI‑DSS** | All payment flows must be tokenized. | Use Amadeus / Sabre tokenization endpoints. |
| **GDPR** | Personal data of EU residents. | Anonymize `passengerInfo` in logs; store only necessary fields. |
| **CORS & CSP** | Protect widget integration. | Set strict `Content-Security-Policy` and `X-Frame-Options: SAMEORIGIN`. |
| **Audit Trail** | Maintain immutable logs. | Store each request/response in PostgreSQL `audit_log` table with `uuid`. |
| **Rate Limiting** | Guard against API abuse. | Use Kong API gateway with `rate_limit` plugins. |

## 9. Sample API Calls & Code Snippets  

### 9.1. Flight Search (Node.js)

```js
const axios = require('axios');
const token = await getAuthToken(); // OAuth2

const res = await axios.get('https://api.amadeus.com/v1/flight/search', {
  headers: { Authorization: `Bearer ${token}` },
  params: {
    origin: 'IST',
    destination: 'LHR',
    departureDate: '2026-12-15',
    cabinPreference: 'economy',
    passengerCount: 1
  }
});
console.log(res.data);
```

```python
import requests, os

headers = {'Authorization': f'Bearer {os.getenv("CRS_TOKEN")}'}
payload = {
    'location': 'IST',

    'rooms': 1,
    'adults': 2

print(response.json())
```

## 10. Performance & Scalability  

- **Caching** – Use Redis TTL of 30 s for flight and hotel search results.  
- **Batching** – Group seat map requests for multiple flights to reduce round‑trips.  
- **Horizontal Scaling** – Deploy API services on Kubernetes with HPA based on CPU/Memory.  
- **Observability** – OpenTelemetry traces for every GDS/CRS call; Grafana dashboards for latency.

## 13. Troubleshooting & Support  

| Symptom | Likely Cause | Remedy |
|---------|--------------|--------|
| **No flight availability returned** | API throttle or data lag | Check `flight_availability` Kafka lag. |
| **Hotel rates mismatch** | Currency conversion issue | Verify CRS `Currency` field against ISO‑4217. |
| **Widget load fails** | CORS mis‑config | Add `Access-Control-Allow-Origin` header. |
| **Booking reference missing** | Authorization token expired | Refresh OAuth token before API call. |

> **Support** – Submit tickets to `gds-support@yourcompany.com` (24/7).
