## 1. Data Landscape

| Source | Scope | Data Granularity | API Endpoint | Auth |
|--------|-------|------------------|--------------|------|
| **Amadeus** | Global flight schedules, seat inventory, cabin classes | *Per‑flight* (SCT, SDE, etc.) | `/v2/shopping/flight-offers` | OAuth 2.0 |
| **Sabre** | Flight availability & booking | *Per‑flight* | `/booking/air/v1/flight` | OAuth 2.0 |
| **Central Reservation System (CRS) – Istanbul Hotels** | Hotel property rates & inventory | *Per‑property* | `/hotel/rates` | API key / OAuth |
| **Istanbul Airport (IST) Real‑Time Schedules** | Flight departure/arrival, delays | *Live* | `/flightstatus/ist` | OAuth 2.0 |

> **Key Insight:** All data is pulled directly from the GDS/CRS in real time, eliminating the need for any affiliate or aggregator layer.

## 2. High‑Level Architecture

```
┌─────────────────────┐      HTTPS       ┌─────────────────────┐
│   Front‑end Portal   │◄────────────────►│   GDS/CRS Gateway   │
└─────────────────────┘  (REST / GraphQL) └─────────────────────┘
          ▲                                        ▲
          │                                        │
          │  OAuth 2.0 + API Keys (Secured)        │
          │                                        │
┌─────────────────────┐      Webhooks     ┌─────────────────────┐
│  Analytics Engine   │◄────────────────►│  Event & Cache Layer │
└─────────────────────┘                  └─────────────────────┘
```

- **Gateway Layer**: Central API orchestrator that normalizes Amadeus & Sabre responses into a unified schema.  
- **Event & Cache Layer**: Redis/Memcached for session‑level caching (TTL ≤ 30 s) to meet SLA for *real‑time* data.  
- **Analytics Engine**: Aggregates flight‑price trends, dynamic cabin mix, hotel yield metrics.

## 3. Flight Search & Seat Booking

### 3.1 Search Flow

1. **User Input** – Origin, Destination, Dates, Cabin Class, Passengers.  
2. **Gate‑API Call**  
   ```http
   POST /api/flight-search
   {
     "origin": "IST",
     "destination": "LHR",
     "departureDate": "2026-11-01",
     "returnDate": "2026-11-10",
     "cabinClass": "Economy",
     "passengers": 2
   }
   ```
3. **GDS Query** – Gateway translates into Amadeus & Sabre queries:
   - **Amadeus**: `GET /v2/shopping/flight-offers?originLocationCode=IST&destinationLocationCode=LHR&departureDate=2026-11-01&adults=2&travelClass=ECONOMY`  
   - **Sabre**: `GET /booking/air/v1/flight?origin=IST&dest=LHR&date=2026-11-01&cabin=Y`
4. **Merge & Rank** – Unified flight offer list sorted by price, duration, or user preference.  
5. **Return to Front‑end** – JSON with:
   - Flight segments
   - Live seat availability per cabin class
   - Pricing breakdown (fare, taxes, fees)

### 3.2 Direct Seat Booking

- **Widget Insertion** – `[GDS_FLIGHT_SEARCH_WIDGET]` embeds a UI component that triggers the same flow, but also opens a modal with the *booking* endpoint.  
- **Booking API**  
   ```http
   POST /api/flight-book
   {
     "offerId": "AF12345",
     "payment": {...},
     "passengerDetails": [...]
   }
   ```  
- **Transactional Guarantee** – All bookings are confirmed via the GDS's `BookingConfirm` API; no pre‑payment hold is stored outside the GDS.

### 3.3 Live Cabin Class Availability

- Response structure includes `availableSeats` per cabin.  
- Example:  
  ```json
  {
     "cabinClass":"PremiumEconomy",
     "availableSeats": 12,
     "fareDetails": [...]
  }
  ```

## 4. Hotel Inventory & Rate Management

### 4.1 Live Rate Retrieval

1. **Hotel Search** –  
   ```http
   POST /api/hotel-search
   {
     "location": "IST",
     "checkIn": "2026-11-01",
     "checkOut": "2026-11-05",
     "guests": 2
   }
   ```
2. **CRS Query** – `GET /hotel/rates?city=IST&checkIn=2026-11-01&checkOut=2026-11-05&guests=2`

### 4.2 Rate & Inventory API

| Field | Description |
|-------|-------------|
| `roomType` | e.g., "Deluxe Double" |
| `availableRooms` | Integer |
| `ratePlanId` | CRS‑specific ID |
| `price` | Currency, net + taxes |
| `specialConditions` | e.g., "Non‑refundable", "Free cancellation" |

### 4.3 Direct Hotel Booking

- **Widget Insertion** – `[CRS_HOTEL_INVENTORY_WIDGET]` displays property cards with live rates and an instant “Book Now” button.  
- **Booking Flow** – POST to `/api/hotel-book` with selected `ratePlanId`, guest details, payment token.  
- **Confirmation** – CRS returns a unique `reservationId`; portal stores a local copy for SLA but never caches price.

## 5. Fare & Pricing Analytics

| KPI | Definition | Calculation |
|-----|------------|-------------|
| **Yield** | Average Revenue Per Occupied Room (AROR) / Occupancy | `AROR / Occupancy` |
| **Seat‑Sell‑Rate** | Seats sold / Total seats (per cabin) | `sold / total` |
| **Hotel ADR** | Average Daily Rate | `Sum(price) / #rooms sold` |
| **Dynamic Mix** | Percentage of bookings by cabin/hotel tier | `#bookings cabin / total bookings` |

### 5.1 Data Pipeline

- **Event‑Driven** – Every booking triggers a Kafka event (`flight-booked`, `hotel-booked`).  
- **Batch Analytics** – nightly ETL aggregates into a data lake (`S3/ADLS`).  
- **Real‑time Dashboard** – Grafana/Kibana for instant insights.

### 5.2 Conversion‑Driven Enhancements

- **Price Alerts** – On‑device push when a flight or hotel price drops below user‑set threshold.  
- **Dynamic Pricing** – Real‑time seat allocation algorithm that nudges users to higher‑margin cabins when inventory is low.

| **Throughput** | 500 req/s | Horizontal scaling of API gateway, stateless microservices. |

- Use **GraphQL** for batched flight/hotel queries if needed.  
- Employ **Circuit Breaker** patterns to handle temporary GDS downtime.

## 8. Security & Compliance

- **OAuth 2.0** with `client_credentials` grant for GDS/CRS APIs.  
- **TLS 1.3** for all external calls.  
- **PCI‑DSS** compliant payment integration; no card data stored beyond session.  
- **GDPR** – Personal data only stored for booking confirmation; all session tokens expire within 5 min.
