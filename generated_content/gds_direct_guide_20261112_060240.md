### 2.1 Data Flow

1. **Ingest** – Scheduled ETL jobs + real‑time webhooks capture schedule, inventory, and rate data.  
2. **Normalize** – Map all codes to internal schema: `CarrierCode`, `FlightNumber`, `CabinClass`, `HotelID`, `RateCode`.  
3. **Cache** – 10‑second TTL for seat availability; 30‑second TTL for rates (adjust per SLA).  
4. **Serve** – RESTful/GraphQL endpoints expose data to the widget layer.  

### 2.2 Key API Endpoints

| Service | Endpoint | Method | Purpose |
|---------|----------|--------|---------|
| Flight Search | `/api/v1/flights/search` | POST | Search direct schedules + seat avail |
| Seat Availability | `/api/v1/flights/{flightId}/seats` | GET | Real‑time seat map |
| Hotel Inventory | `/api/v1/hotels/inventory` | GET | Hotel room availability + rates |
| Pricing Engine | `/api/v1/price/calc` | POST | Dynamic fare calculation (taxes, fees) |
| PNR Create | `/api/v1/booking/flight` | POST | Book flight seat & return confirmation |
| PNR Create (Hotel) | `/api/v1/booking/hotel` | POST | Book room & return confirmation |

> **Security**: All endpoints are protected via OAuth 2.0 (client‑credentials grant). JWT tokens contain a `portal_id` claim to enforce tenancy.

## 3. Flight Search & Booking

### 3.1 Flight Search Widget – `[GDS_FLIGHT_SEARCH_WIDGET]`

```html
<div id="flight-widget"
     data-portal="mycorp"
     data-theme="dark"
     data-callback="onFlightSelect">
</div>
<script src="https://cdn.mycorp.com/widgets/gds_flight_search.js"></script>
```

> The widget fetches from `/api/v1/flights/search` and renders:
> - Multi‑segment itineraries  
> - Live cabin class options (Economy, Premium, Business, First)  
> - Seat map pop‑up with real‑time seat availability  
> - Fare breakdown (base fare, taxes, fees, optional services)

#### 3.1.1 API Request Example

```json
POST /api/v1/flights/search
{
  "origin": "IST",
  "destination": "NYC",
  "departureDate": "2026-12-15",
  "returnDate": "2026-12-22",
  "passengers": {
    "adults": 2,
    "children": 1,
    "infants": 0
  },
  "cabinClass": "Economy",
  "currency": "USD",
  "includeDirectOnly": true
}
```

> **Response** – 200 OK (sample)

```json
{
  "searchId": "abc123",
  "itineraries": [
    {
      "flightId": "UA1234",
      "segments": [
        {
          "flightNumber": "UA1234",
          "carrier": "UA",
          "departure": "2026-12-15T08:00:00Z",
          "arrival": "2026-12-15T18:00:00Z",
          "origin": "IST",
          "destination": "NYC",
          "cabinClasses": [
            {"code":"Economy","availability":12,"baseFare":250},
            {"code":"Premium","availability":4,"baseFare":650}
          ]
        },
        ...
      ],
      "totalFare": 1250,
      "currency":"USD",
      "fareBreakdown":[
        {"type":"Base","amount":1200},
        {"type":"Tax","amount":50},
        {"type":"ServiceFee","amount":0}
      ]
    },
    ...
  ]
}
```

> **Key Points**  
> • **Direct Carrier Schedules** – only flights with `includeDirectOnly:true` are returned.  
> • **Live Cabin Class Availability** – `availability` reflects current seat counts.  
> • **Fare Rules** – `fareBreakdown` includes all mandatory charges.

#### 3.1.2 Seat Map & Booking Flow

1. User clicks “Select Seat”.  
2. Widget calls `/api/v1/flights/{flightId}/seats`.  
3. Response includes seat map JSON (e.g., `{"seat":"12A","class":"Economy","available":true}`).  
4. User selects seat → widget calls `/api/v1/booking/flight` with seat assignment.  
5. Backend creates PNR via Amadeus/Sabre PNR API and returns `pnrId`, `ticketNumber`.

> **Important**: Seat selection must be done *before* fare calculation to lock the seat.
