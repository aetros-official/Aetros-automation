## 2. Direct Airline Schedules – Technical Blueprint  

### 2.1 Data Model  

| Field | Type | Description |
|-------|------|-------------|
| `CarrierCode` | `CHAR(2)` | IATA airline designator (e.g., TK, QR) |
| `FlightNumber` | `VARCHAR(6)` | Flight number (numeric portion) |
| `DepartureAirport` | `CHAR(3)` | IATA code (e.g., IST) |
| `ArrivalAirport` | `CHAR(3)` | IATA code |
| `STD` | `TIMESTAMP` | Scheduled Time of Departure (UTC) |
| `STA` | `TIMESTAMP` | Scheduled Time of Arrival (UTC) |
| `OperatingDays` | `BITMASK(7)` | Mon‑Sun bitmap (1 = operates) |
| `AircraftType` | `VARCHAR(4)` | ICAO type (e.g., A320) |
| `EffectiveFrom` | `DATE` | Validity start |
| `EffectiveTo` | `DATE` | Validity end |

### 2.2 Retrieval Endpoint  

```
GET /api/v1/gds/flights?origin=IST&destination={IATA}&date={YYYY-MM-DD}
Headers:
  X-API-KEY: <your‑engine‑key>
  Accept: application/json
```

- **Response:** JSON array of the above data model, sorted by `STD`.  
- **Rate‑limit:** 5000 calls / hour per client (adjustable per SLA).  

### 2.3 Integration Pattern  

```html
<!-- Flight Search Widget – Direct GDS Integration -->
[GDS_FLIGHT_SEARCH_WIDGET]
```

- The widget automatically consumes the `/flights` endpoint, renders an **interactive schedule grid** with **real‑time filtering** (carrier, aircraft, time‑window).  
- Clicking a row triggers a **Seat Map API** call (see § 2.4) and opens the **booking flow** without any affiliate redirects.

### 2.4 Live Cabin Class Availability  

| Cabin | Code | Seats Available (Live) | Fare Basis |
|-------|------|------------------------|------------|
| Economy | `Y` | `int` (real‑time) | `Yxxxx` |
| Premium Economy | `W` | `int` | `Wxxxx` |
| Business | `C` | `int` | `Cxxxx` |
| First | `F` | `int` | `Fxxxx` |

**API Call**  

```
GET /api/v1/gds/seatmap?carrier={CarrierCode}&flight={FlightNumber}&date={YYYY-MM-DD}
```

- Returns a **binary seat‑map payload** (PNG or SVG) plus JSON seat‑status (`available`, `blocked`, `sold`).  
- The widget overlays the seat‑map with **color‑coded cabin classes** and enables **direct seat selection**.

## 3. Official Hotel CRS Rates – Technical Blueprint  

### 3.1 Data Model  

| Field | Type | Description |
|-------|------|-------------|
| `HotelID` | `UUID` | Unique CRS identifier |
| `PropertyCode` | `VARCHAR(10)` | Hotel chain code |
| `RoomTypeCode` | `VARCHAR(8)` | CRS room type (e.g., DBL, SGL) |
| `RatePlanCode` | `VARCHAR(12)` | Rate‑plan identifier (e.g., BAR, NONREF) |
| `Currency` | `CHAR(3)` | ISO 4217 |
| `BaseRate` | `DECIMAL(12,2)` | Net rate before taxes |
| `TaxAmount` | `DECIMAL(12,2)` | Applicable taxes |
| `TotalRate` | `DECIMAL(12,2)` | Base + Tax |
| `Availability` | `INT` | Live inventory count |
| `CheckInDate` | `DATE` | Arrival |
| `CheckOutDate` | `DATE` | Departure |
| `EffectiveFrom` | `TIMESTAMP` | Rate‑plan start |
| `EffectiveTo` | `TIMESTAMP` | Rate‑plan end |

### 3.2 Retrieval Endpoint  

```
POST /api/v1/crs/hotels/search
Headers:
  X-API-KEY: <your‑engine‑key>
  Content-Type: application/json
Body:
{
  "destination": "IST",
  "check_in": "2024-12-20",
  "check_out": "2024-12-27",
  "rooms": [
    {"adults":2,"children":0}
  ],
  "filters": {
    "min_price": 0,
    "max_price": 1000,
    "amenities": ["wifi","breakfast"]
  }
}
```

- **Response:** Paginated JSON list of `HotelID` objects with live `Availability` and `TotalRate`.  

### 3.3 Integration Pattern  

```html
<!-- Hotel Inventory Widget – Direct CRS Integration -->
[CRS_HOTEL_INVENTORY_WIDGET]
```

- The widget renders a **search‑results grid** with **price‑sorted listings**, live availability badges, and **rate‑plan tags** (e.g., “BAR – Best Available Rate”).  
- Selecting a property opens a **room‑type detail view** that calls the **Rate‑Detail API** (see below) and proceeds to a **secure booking engine** that writes directly to the CRS reservation queue.  

### 3.4 Rate‑Detail API (Optional)  

```
GET /api/v1/crs/hotels/{HotelID}/rates?room_type={RoomTypeCode}&date_range={YYYY-MM-DD}_{YYYY-MM-DD}
```

- Returns a **price matrix** (per night) and **cancellation policy** text blocks.

## 4. End‑to‑End Booking Flow (Zero Affiliate Dependency)  

1. **User searches** flights via `[GDS_FLIGHT_SEARCH_WIDGET]`.  
2. **Live schedule** and **cabin class** data populate instantly.  
3. **Seat selection** triggers the seat‑map API; reservation is **Pushed to the GDS PNR engine** (PNR creation via `/pnr/create`).  
4. **User searches** hotels via `[CRS_HOTEL_INVENTORY_WIDGET]`.  
5. **Live rates** and **inventory** are displayed; user selects room & rate plan.  
6. **Reservation** is posted to the CRS (`/reservation/create`) – **no affiliate markup**.  
7. **Confirmation** payload includes **GDS PNR locator** and **CRS reservation code**, both returned in a **single JSON response** for downstream CRM/ERP sync.

## 5. Security & Compliance  

| Aspect | Implementation |
|--------|----------------|
| **Authentication** | Mutual TLS + API‑Key (rotatable every 90 days). |
| **Authorization** | Role‑Based Access Control (RBAC) – `flight_read`, `flight_write`, `hotel_read`, `hotel_write`. |
| **Data Encryption** | TLS 1.3 end‑to‑end; at‑rest AES‑256 for cached rate tables. |
| **PCI DSS** | Booking engine isolates payment tokenization to a PCI‑validated vault; no card data traverses GDS/CRS layers. |
| **GDPR / Data Residency** | Personal data (PNR, guest name) stored in EU‑region data centers; explicit consent flag required before PNR creation. |
| **Audit Trail** | Every GDS/CRS transaction logged with immutable SHA‑256 hash for forensic review. |

## 8. Frequently Asked Technical Questions  

| Q | A |
|---|---|
| **Do the widgets cache data?** | No. All calls are **live** to the GDS/CRS endpoints. The widget only caches UI assets (HTML/CSS/JS) for < 5 min to reduce CDN load. |
| **Can I filter by airline alliance?** | Yes – add `alliance=star` (or `oneworld`, `skyteam`) to the flight search query string. |
| **How are rate‑plan restrictions (e.g., closed‑to‑arrival) enforced?** | The CRS returns a `restriction` object; the widget disables the “Book Now” button and displays the policy tooltip. |
| **Is there a bulk‑download option for schedule data?** | A nightly **FlatFile** (`.csv.gz`) dump is available via `/batch/schedules?date=YYYY-MM-DD`. Use only for analytics – not for real‑time booking. |
| **What SLA applies to data freshness?** | 99 % of schedule updates are reflected within **2 seconds** of carrier publish; hotel rates within **15 seconds** of CRS rate change. |
