# 📘 Core AI Engine – Travel & Fare Analysis Guide  
*(White‑Label Direct Booking Integration – 2026‑11‑19)*  

> **Purpose** – This document is the definitive, technically‑rich reference for integrating **live flight and hotel data** from the **Amadeus/Sabre Core Engine** and **CRS (Central Reservation System)** into any enterprise travel portal.  
> **Audience** – Backend architects, API developers, QA engineers, and product owners working on a direct‑booking experience.  
> **Scope** – Full‑stack journey from GDS/CRS data acquisition to rendering in a white‑label widget. No affiliate or third‑party pricing layers are used – all rates, schedules and inventory come directly from the source.

## 2. Raw Live GDS/CRS Data

### 2.1 Flight Data – Amadeus / Sabre Core Engine

| Field | Description | Example |
|-------|-------------|---------|
| `flightNumber` | Carrier flight number | `LH123` |
| `departureDateTime` | UTC ISO 8601 | `2026-12-01T12:30:00Z` |
| `arrivalDateTime` | UTC ISO 8601 | `2026-12-01T16:00:00Z` |
| `origin` | IATA code | `IST` |
| `destination` | IATA code | `LHR` |
| `cabinClasses` | List of `Cabin` objects | `[{class:"Y", availability:5, price:€120}]` |
| `airlineCode` | IATA carrier code | `LH` |
| `equipment` | Aircraft type | `Boeing 737-800` |
| `status` | `ON_TIME`, `DELAYED`, `CANCELLED` | `ON_TIME` |

**Live Cabin Class Availability** – Each flight returns an array of cabin objects; the `availability` field is guaranteed to be real‑time. The `price` field is the current fare (inclusive of taxes). Rates are updated every 5 s on average; our caching layer respects a `Cache-Control: max-age=5`.

### 2.2 Hotel Data – CRS Real‑Time Inventory

| Field | Description | Example |
|-------|-------------|---------|
| `propertyId` | CRS internal ID | `HR001` |
| `hotelName` | Full name | `Hotel Istanbul Plaza` |
| `roomType` | Standard/Deluxe/etc | `Deluxe Suite` |
| `availability` | Integer | `3` |
| `rate` | Currency ISO + amount | `EUR 210.00` |
| `cancellationPolicy` | Text | `Free cancellation until 48h` |
| `checkIn` | Date | `2026-12-04` |
| `checkOut` | Date | `2026-12-07` |

*Rates are pulled from the CRS via the `hotelSearch` API and refreshed every 10 s.*

## 3. White‑Label Direct Booking Widgets

### 3.1 Flight Search Widget – `[GDS_FLIGHT_SEARCH_WIDGET]`

> **Goal** – A self‑contained React component that exposes a flight search UI and communicates with the backend via GraphQL.

#### API Contract

```graphql
# Query
query FlightSearch($origin: String!, $dest: String!, $date: String!, $cabin: String) {
  flightSearch(origin: $origin, dest: $dest, date: $date, cabin: $cabin) {
    flightNumber
    departureDateTime
    arrivalDateTime
    airlineCode
    cabinClasses {
      class
      availability
      price
    }
  }
}

# Mutation (Booking)
mutation BookFlight($flightId: ID!, $cabin: String!, $passengers: [PassengerInput!]!) {
  bookFlight(flightId: $flightId, cabin: $cabin, passengers: $passengers) {
    bookingRef
    status
    totalAmount
  }
}
```

> **Integration** – The widget loads data via `useQuery` (Apollo) and dispatches the `BookFlight` mutation when a user confirms a seat.

> **Security** – All requests go over HTTPS and contain a bearer token from our SSO system. The widget does *not* expose any affiliate tracking codes.

### 3.2 Hotel Inventory Widget – `[CRS_HOTEL_INVENTORY_WIDGET]`

> **Goal** – A Vue component that lists rooms in real‑time and allows direct booking.

#### API Contract

```graphql
# Query
query HotelSearch($city: String!, $checkIn: String!, $checkOut: String!) {
  hotelSearch(city: $city, checkIn: $checkIn, checkOut: $checkOut) {
    propertyId
    hotelName
    roomType
    availability
    rate
    cancellationPolicy
  }
}

# Mutation (Booking)
mutation BookHotel($propertyId: ID!, $roomType: String!, $checkIn: String!, $checkOut: String!) {
  bookHotel(propertyId: $propertyId, roomType: $roomType, checkIn: $checkIn, checkOut: $checkOut) {
    bookingRef
    status
    totalAmount
  }
}
```

> **Real‑Time Sync** – The widget polls the GraphQL endpoint every 7 s to refresh availability. Alternatively, use a WebSocket subscription for instant updates.

## 4. Fare & Inventory Analysis Pipeline

1. **Data Ingestion**  
   - **Flight**: Scheduled `POST /v3.1/flight/availability` every 5 s.  
   - **Hotel**: Scheduled `POST /v3.1/hotelSearch` every 10 s.

2. **Normalization**  
   - Convert timestamps to UTC + local timezone.  
   - Map cabin codes (`Y`, `C`, `F`) to internal `classId` enum.  
   - Convert CRS `rate` into a unified `Fare` object (amount, currency, taxes).

3. **Caching Strategy**  
   - Redis TTL = 10 s (flight) / 15 s (hotel).  
   - Cache key pattern: `flight:{origin}:{dest}:{date}:{cabin}` and `hotel:{city}:{checkIn}:{checkOut}`.

4. **Pricing Engine**  
   - Apply dynamic rules:  
     - **Fare Boost** for low availability (`availability < 3`).  
     - **Seasonal Adjustment** for holiday periods.  
     - **Last‑minute Discount** if `checkIn < now + 48h`.  

5. **Rule Evaluation**  
   ```python
   def adjust_price(base, availability, season_factor):
       if availability < 3:
           base *= 1.15  # 15% surge
       base *= season_factor
       return round(base, 2)
   ```

6. **Audit Trail**  
   - Every search and booking logs: `timestamp`, `userId`, `query`, `resultCount`, `bookingRef`.  
   - Stored in ElasticSearch for compliance queries.

## 8. Sample Code Snippets

### 8.1 Flight Query (React)

```jsx
import { useQuery } from '@apollo/client';
import gql from 'graphql-tag';

const FLIGHT_SEARCH = gql`
  query FlightSearch($origin: String!, $dest: String!, $date: String!, $cabin: String) {
    flightSearch(origin: $origin, dest: $dest, date: $date, cabin: $cabin) {
      flightNumber
      departureDateTime
      arrivalDateTime
      airlineCode
      cabinClasses { class availability price }
    }
  }
`;

export const GDS_FLIGHT_SEARCH_WIDGET = ({ origin, dest, date, cabin }) => {
  const { loading, error, data } = useQuery(FLIGHT_SEARCH, {
    variables: { origin, dest, date, cabin },
  });

  if (loading) return <p>Loading…</p>;
  if (error) return <p>Error: {error.message}</p>;

  return (
    <div>
      {data.flightSearch.map(f => (
        <div key={f.flightNumber}>
          <h3>{f.airlineCode} {f.flightNumber}</h3>
          <p>{new Date(f.departureDateTime).toLocaleTimeString()} → {new Date(f.arrivalDateTime).toLocaleTimeString()}</p>
          {f.cabinClasses.map(c => (
            <div key={c.class}>
              {c.class}: €{c.price} (Seats: {c.availability})
            </div>
          ))}
        </div>
      ))}
    </div>
  );
};
```

## 9. FAQs

| Question | Answer |
|----------|--------|
| **Do we ever cache rates longer than 15 s?** | No – all rates must be real‑time to comply with GDS/CRS terms. |
| **Can we integrate with a third‑party price comparison engine?** | Not for the “no‑affiliate” requirement. All data must come from the native GDS/CRS. |
| **How to handle flight cancellations?** | The `status` field will be set to `CANCELLED`. Trigger a UI alert and remove seat from cart. |
| **What about multi‑stop itineraries?** | FlightSearch can accept `origin`, `dest`, `date` + `stops: 1` to get connecting flight data. |
