## 1. Executive Overview  

The **Enterprise Travel Portal** is a white‑label, high‑throughput booking front‑end that consumes **only** live data from the **Amadeus / Sabre Core Engine** (airline schedules, cabin‑class availability) and the **Central Reservation System (CRS)** for hotels in Istanbul (IST).  

* **Zero reliance on third‑party affiliate networks** – every fare, seat, and room rate originates from the carrier’s GDS or the hotel’s CRS.  
* Designed for **sub‑millisecond latency** on the Groq LPU inference path, enabling real‑time price‑sensitivity calculations and dynamic conversion optimization.  

---  

## 2. Source Data Specification  

| Domain | Source | Feed Type | Update Frequency | Key Fields |
|--------|--------|-----------|------------------|------------|
| **Airline Schedules** | Amadeus / Sabre Core Engine | OTA‑AirLow‑Fare‑Search (XML/JSON) | Every 30 seconds (push) | `CarrierCode`, `FlightNumber`, `DepartureDateTime`, `ArrivalDateTime`, `Origin`, `Destination`, `OperatingAirline`, `Equipment`, `MarketingAirline` |
| **Cabin‑Class Availability** | Amadeus / Sabre Core Engine | OTA‑AirLow‑Fare‑Availability (XML/JSON) | Every 15 seconds (push) | `CabinClass` (Y/E/B/F), `SeatsAvailable`, `FareBasis`, `TicketDesignator`, `BaggageAllowance`, `Refundability` |
| **Hotel CRS Rates** | Central Reservation System (CRS) – Direct hotel contracts | CRS‑Hotel‑Rate‑Feed (JSON) | Every 10 seconds (push) | `HotelID`, `PropertyName`, `RoomTypeCode`, `RatePlanCode`, `Currency`, `BaseRate`, `Tax`, `TotalRate`, `AvailabilityCount`, `CancellationPolicy` |

> **Note** – All feeds are delivered over **TLS‑1.3** with **mutual certificate authentication**.

## 3. Direct Airline Schedule & Cabin‑Class Model  

### 3.1 Data Normalization  

| Normalized Field | Source Path | Type | Description |
|------------------|-------------|------|-------------|
| `airline_code` | `CarrierCode` | string(2) | IATA carrier identifier |
| `flight_number` | `FlightNumber` | string | Numeric part (e.g., “1234”) |
| `departure_utc` | `DepartureDateTime` | ISO‑8601 | UTC timestamp |
| `arrival_utc` | `ArrivalDateTime` | ISO‑8601 | UTC timestamp |
| `origin_iata` | `Origin` | string(3) | Airport code |
| `dest_iata` | `Destination` | string(3) | Airport code |
| `cabin_class` | `CabinClass` | enum(Y,E,B,F) | Economy, Premium, Business, First |
| `seats_available` | `SeatsAvailable` | integer | Real‑time inventory |
| `fare_basis` | `FareBasis` | string | Pricing rule identifier |
| `ticket_designator` | `TicketDesignator` | string | Ticketing restrictions |
| `baggage_allowance` | `BaggageAllowance` | string | E.g., “2PC” |
| `refundable` | `Refundability` | boolean | True/False |

### 3.2 Pricing Engine Input  

```json
{
  "airline_code": "TK",
  "flight_number": "1234",
  "departure_utc": "2026-10-15T08:30:00Z",
  "cabin_class": "Y",
  "seats_available": 12,
  "fare_basis": "Y1A",
  "base_fare": 185.00,
  "currency": "EUR",
  "taxes": [
    {"code":"US","amount":15.00},
    {"code":"YY","amount":8.50}
  ]
}
```

The **Pricing Engine** (Groq LPU) consumes the above JSON, applies corporate fare‑rules, and returns a **net fare** with optional corporate markup or discount.

## 4. Real‑Time CRS Hotel Rate Model  

### 4.1 Data Normalization  

| Normalized Field | Source Path | Type | Description |
|------------------|-------------|------|-------------|
| `hotel_id` | `HotelID` | string | Unique CRS identifier |
| `property_name` | `PropertyName` | string | Official hotel name |
| `room_type_code` | `RoomTypeCode` | string | CRS room type |
| `rate_plan_code` | `RatePlanCode` | string | Rate plan (e.g., “BAR”, “CORP”) |
| `currency` | `Currency` | string(3) | ISO 4217 |
| `base_rate` | `BaseRate` | decimal | Net room price before tax |
| `tax` | `Tax` | decimal | Aggregated tax amount |
| `total_rate` | `TotalRate` | decimal | `base_rate + tax` |
| `availability` | `AvailabilityCount` | integer | Live inventory |
| `cancellation_policy` | `CancellationPolicy` | string | Human‑readable policy snippet |

### 4.2 Rate Calculation Example  

```json
{
  "hotel_id": "IST001",
  "property_name": "The Grand Istanbul",
  "room_type_code": "DLX",
  "rate_plan_code": "CORP",
  "currency": "USD",
  "base_rate": 210.00,
  "tax": 32.00,
  "total_rate": 242.00,
  "availability": 5,
  "cancellation_policy": "Free cancellation up to 24h before check‑in"
}
```

All rates are **published in the currency requested by the portal**; the CRS provides a **real‑time FX conversion table** (via a separate secure feed) that the portal must apply before display.

## 5. Integration Architecture  

```mermaid
flowchart TD
    subgraph Front‑End
        UI[User Interface] --> GDS_WIDGET[[GDS_FLIGHT_SEARCH_WIDGET]]
        UI --> CRS_WIDGET[[CRS_HOTEL_INVENTORY_WIDGET]]
    end
    subgraph API Layer
        GDS_API[GET /gds/flights] -->|JSON| GDS_Service[Amadeus/Sabre Core Engine]
        CRS_API[GET /crs/hotels] -->|JSON| CRS_Service[Hotel CRS]
        PricingEngine[Groq LPU Pricing Service]
    end
    subgraph Data Store
        Cache[In‑Memory Redis (TTL 30 s)] 
    end

    GDS_WIDGET --> GDS_API
    CRS_WIDGET --> CRS_API
    GDS_API --> Cache
    CRS_API --> Cache
    Cache --> PricingEngine
    PricingEngine --> UI
```

### Key Architectural Decisions  

| Decision | Rationale |
|----------|-----------|
| **Stateless REST endpoints** | Enables horizontal scaling behind a load balancer. |
| **Edge cache (Redis) with 30‑second TTL** | Guarantees sub‑second response while respecting live GDS/CRS freshness. |
| **Groq LPU inference for fare optimization** | Leverages ultra‑low latency for dynamic pricing and conversion uplift. |
| **Mutual TLS + JWT** | End‑to‑end authentication and integrity for all internal calls. |
| **No third‑party affiliate IDs** | Guarantees 0 % affiliate dependency, meeting the requirement. |

## 6. API Contract (REST/JSON)  

### 6.1 Flight Search Endpoint  

```
GET /api/v1/gds/flights
```

**Query Parameters**  

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `origin` | string(3) | Yes | IATA origin airport |
| `destination` | string(3) | Yes | IATA destination airport |
| `departure_date` | YYYY‑MM‑DD | Yes | Local departure date |
| `cabin` | enum(Y,E,B,F) | No | Preferred cabin (default = Y) |
| `adults` | integer | Yes | Number of adult pax |
| `children` | integer | No | Number of child pax |
| `currency` | string(3) | No | Desired currency (default = EUR) |
| `max_price` | decimal | No | Upper price bound |

### 6.3 Error Model  

All error responses follow the **RFC 7807** problem‑details format. Example (404 – No Results):

```json
{
  "type": "https://api.example.com/errors/no-results",
  "title": "No Results Found",
  "status": 404,
  "detail": "No flights match the supplied criteria.",
  "instance": "/api/v1/gds/flights?origin=IST&destination=XYZ"
}
```
