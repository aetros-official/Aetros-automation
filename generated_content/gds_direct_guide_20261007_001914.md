## 2. Data Foundations  

### 2.1 GDS Flight Data  
| Field | Description | Example |
|-------|-------------|---------|
| `flight_number` | Carrier flight number | `LH 123` |
| `departure_time` | UTC ISO‑8601 | `2024-11-01T08:15:00Z` |
| `arrival_time` | UTC ISO‑8601 | `2024-11-01T12:45:00Z` |
| `cabin_class` | E.g., `Y` (Economy), `J` (Business), `F` (First) | `J` |
| `available_seats` | Number of seats left | `5` |
| `fare_basis` | Pricing rule identifier | `Y2A` |
| `price` | Currency and amount | `EUR 420.00` |
| `currency` | Currency code | `EUR` |

*All flight data is sourced in real‑time from the Amadeus/Sabre Core Engine using the `Flight Offers Search` API.*

### 2.2 CRS Hotel Data  
| Field | Description | Example |
|-------|-------------|---------|
| `hotel_id` | CRS unique property identifier | `IST1234` |
| `room_type` | e.g., `Standard`, `Suite` | `Suite` |
| `available_rooms` | Count | `12` |
| `rate` | Per‑night price | `EUR 149.00` |
| `cancellation_policy` | Text or code | `C14` |
| `rate_code` | CRS rate identifier | `R1234` |
| `guests_per_room` | Max occupancy | `2` |

*All hotel inventory and rates come directly from the CRS for Istanbul (IST).*

## 4. White‑Label Widget Blueprint  

### 4.1 Flight Search & Booking Widget  
Place the following placeholder wherever you want the flight booking flow to appear.

```markdown
[GDS_FLIGHT_SEARCH_WIDGET]
```

**How it works**

1. **Flight Search** – User enters origin, destination, dates, passengers.  
2. **Live Offer Fetch** – Widget calls the `Flight Offers Search` API and receives real‑time cabin availability.  
3. **Dynamic Pricing UI** – Prices are displayed with currency symbols and fare‑basis codes.  
4. **Seat Selection** – On booking, the widget shows live seat maps (if supported by GDS).  
5. **Payment** – Passes the booking context to your payment gateway (PCI‑DSS compliant).  
6. **Confirmation** – Returns ticket details directly from the carrier.

> **Conversion Hook**: Highlight `Lowest Price Guaranteed` and `Free Cancellation` for specific cabin classes.

### 4.2 Hotel Inventory & Booking Widget  
Insert the following placeholder for hotel booking.

```markdown
[CRS_HOTEL_INVENTORY_WIDGET]
```

**How it works**

1. **Search Criteria** – Destination (IST), check‑in/out, guests.  
2. **Real‑time Rate Retrieval** – Widget calls CRS `Hotel Availability` endpoint.  
3. **Room Type & Rate Display** – Shows room types, nightly rates, and total.  
4. **Booking Flow** – Guest details → instant confirmation → CRS booking reference.  
5. **Post‑Booking** – Sends confirmation email through your own system.

> **Conversion Hook**: Display `Instant Booking` and `Price Match Guarantee`.

## 5. API Integration  

### 5.1 Auth & Session Management  

| Step | Endpoint | Request | Response |
|------|----------|---------|----------|
| 1 | `POST /token` | `{ "client_id": "...", "client_secret": "...", "grant_type": "client_credentials" }` | `{ "access_token": "...", "expires_in": 3600 }` |
| 2 | `GET /session` | `Authorization: Bearer <access_token>` | `{ "session_id": "...", "valid_until": "2024-12-01T00:00:00Z" }` |

*Use `session_id` for all subsequent GDS/CRS calls to maintain a consistent booking context.*

## 6. Conversion Best Practices  

| Practice | Why | How to Implement |
|----------|-----|------------------|
| **Price Anchoring** | Show a "Highest Price" tag to increase perceived value. | Use historical high fare data (cached) next to real‑time price. |
| **Dynamic Availability Badges** | Instantly show `Only 3 seats left`. | Bind `available_seats` to a real‑time counter via WebSocket or server‑sent events. |
| **One‑Click Book** | Reduce friction for frequent travelers. | Pre‑fill user profile data and store `session_id` to skip repeated credential steps. |
| **Instant Confirmation** | Trust is built when travelers receive instant e‑tickets. | Call the GDS `ticketing` endpoint immediately after payment and stream the PDF to the user. |
| **Localized Currency** | Users trust local prices. | Convert rates with the most recent FX feed, but always display the original currency next to the converted value. |
| **Responsive Design** | Mobile bookings account for >50% of traffic. | Test widgets on iOS/Android browsers and ensure touch‑friendly seat maps. |
| **Accessibility** | Inclusive UX improves conversion and compliance. | Follow WCAG 2.1 AA standards for color contrast and screen‑reader labels. |

## 8. Security & Compliance  

- **PCI‑DSS**: All card data passes through your payment gateway; no card numbers stored.  
- **GDPR**: Store personal data only in EU‑resident databases; provide opt‑out for marketing.  
- **OAuth 2.0**: Token revocation and short lifetimes (≤1 h).  
- **Data Encryption**: TLS 1.3 for all outbound/inbound traffic.

## 9. FAQs & Troubleshooting  

| Question | Answer |
|----------|--------|
| *Why is my flight not showing up?* | Check that the carrier and airport codes are correct. Some itineraries may have no seats for the requested cabin. |
| *What if I get a 429 “Too Many Requests”?* | The GDS/CRS enforces rate limits. Implement exponential back‑off and cache results for 60 s. |
| *Can I customize cabin class labels?* | Yes—map `cabin_code` to your brand terminology (`Economy`, `Premium Economy`, etc.). |
| *How do I handle multi‑city itineraries?* | Pass multiple `segments` to the `Flight Offers Search` endpoint or chain separate searches. |
| *Is there a way to show dynamic price alerts?* | Subscribe to a GDS price monitoring webhook (if available) and push price changes to the client via WebSocket. |
