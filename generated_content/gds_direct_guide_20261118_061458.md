## 3. Flight Data Architecture

### 3.1 Data Model

| Field | Type | Description |
|-------|------|-------------|
| `FlightNumber` | `string` | e.g., `AA1234` |
| `DepartureDateTime` | `ISO8601` | UTC |
| `ArrivalDateTime` | `ISO8601` | UTC |
| `Origin` | `IATA` | e.g., `JFK` |
| `Destination` | `IATA` | e.g., `LHR` |
| `CabinClasses` | `array` | Each containing `ClassCode`, `SeatsAvailable`, `FareBasis`, `Price`, `Tax`, `ValidityPeriod` |
| `FareRules` | `object` | Refundability, baggage, change policy |
| `AirlineCode` | `IATA` | e.g., `AA` |
| `OperatingCarrier` | `IATA` | If codeshare |
| `SegmentType` | `string` | `direct`, `stopover` |
| `FlightStatus` | `enum` | `on_time`, `delayed`, `cancelled` |

### 3.2 API Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/flights/search` | `POST` | Search by date, origin/destination, cabin, price range. |
| `/flights/availability` | `GET` | Get seat availability for a flight + cabin. |
| `/flights/price` | `GET` | Get current fare for a cabin, including taxes. |
| `/flights/rules` | `GET` | Retrieve fare rules for a given fare basis. |

### 3.3 Pricing & Taxation

- **Base Fare** – Raw airline fare.  
- **Taxes** – Summed across all applicable national and airport taxes.  
- **Fees** – Booking fee, reservation fee (if applicable).  
- **Currency Conversion** – Real‑time rates via **Open Exchange Rates** (integrated within Core AI).

> **Conversion Rate:** All prices displayed in the traveler’s currency; stored in USD for accounting.

### 3.4 Availability Refresh

- **Push Notifications** from GDS for seat changes.  
- **Polling** at 2‑minute intervals for high‑traffic routes.

## 4. Hotel Data Architecture

### 4.1 Data Model

| Field | Type | Description |
|-------|------|-------------|
| `HotelId` | `string` | CRS internal ID |
| `Name` | `string` | Hotel name |
| `Address` | `object` | `street`, `city`, `state`, `country`, `lat`, `lon` |
| `StarRating` | `int` | 0‑5 |
| `RoomTypes` | `array` | Each with `RoomId`, `Description`, `Capacity`, `Rate`, `Availability`, `RateCode`, `Tax` |
| `RatePlan` | `object` | `CancellationPolicy`, `CheckIn`, `CheckOut`, `MinStay` |
| `Images` | `array` | URLs |
| `Amenities` | `array` | e.g., `wifi`, `pool` |
| `GuestReviews` | `object` | Average rating, count |

### 4.2 API Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/hotels/search` | `POST` | Search by city, dates, star rating, price range. |
| `/hotels/availability` | `GET` | Get real‑time room inventory. |
| `/hotels/rate` | `GET` | Current rate for a room type. |
| `/hotels/book` | `POST` | Confirm reservation and generate CRS confirmation number. |

### 4.3 Rate Management

- **Dynamic Pricing** – Adjusted by CRS in real‑time based on demand.  
- **Promotions** – Applied at booking time, no need for separate affiliate offers.  
- **Rate Codes** – Map to fare families; used for reporting.

## 5. White‑Label Booking Integration

### 5.1 Architecture Overview

1. **Client UI** – Your brand’s frontend (React/Vue/Angular).  
2. **Core AI Engine** – Node.js microservice handling GDS/CRS calls, business logic, and caching.  
3. **Database** – PostgreSQL (audit, logs, user sessions).  
4. **Auth Layer** – OAuth2.0 / JWT for secure API access.  
5. **Widget Layer** – Embeddable iframes or SPA components.

```
Client UI
   │
   ├─► Core AI Engine (API Gateway)
   │    ├─► GDS/CRS APIs
   │    ├─► Pricing Engine
   │    └─► Booking Engine
   │
   └─► Database (Audit, Analytics)
```

### 5.2 Key Business Rules

| Rule | Implementation |
|------|----------------|
| **No Affiliate Margin** | All booking data goes through Core AI → CRS. |
| **Real‑Time Seat Allocation** | Immediate reservation via CRS API; hold for 10 min if payment pending. |
| **Dynamic Pricing** | Pull latest fare before confirmation; lock price via CRS if possible. |
| **Compliance** | PCI‑DSS compliant payment gateway; GDPR‑ready user data handling. |
