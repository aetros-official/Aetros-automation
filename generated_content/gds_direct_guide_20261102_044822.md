## 4. Technical Integration Specifications for White-Label Deployment

To maintain **0% dependency on third-party affiliate networks**, your frontend backend must adhere to the following core engine protocols:

### A. GDS / PNR Creation Protocol
1.  **Endpoint:** `POST /api/v1/gds/create_pnr`
2.  **Payload Structure:**
    ```json
    {
      "loc_code": "IST",
      "passenger_details": [ ... ],
      "segment": {
        "carrier": "TK",
        "flight_num": "112",
        "date": "2023-10-25",
        "fare_basis": "TJY",
        "cabin": "J"
      },
      "billing_info": {
        "corp_account_id": "CORP_88921",
        "payment_token": "DIRECT_CARRIER_TOKEN"
      }
    }
    ```
3.  **Response Handling:**
    *   **Success:** Return `PNR_ID` and `Carrier_Confirm_Code`.
    *   **Failure (Sold Out):** Trigger immediate re-query of next best fare in same cabin class.

### B. CRS / Hotel Booking Protocol
1.  **Endpoint:** `POST /api/v1/crs/reserve_room`
2.  **Validation Logic:**
    *   Verify `rate_code` matches `property_code`.
    *   Check `cancellation_policy_window` against current server time.
    *   Validate `max_stays` limit.
3.  **Confirmation:**
    *   Instant issuance of `CRS_Res_ID`.
    *   No intermediary redirect; payment processed via secure direct gateway.

### C. Security & Compliance
*   **GDPR/CCPA Compliance:** Passenger PII encrypted at rest (AES-256) and in transit (TLS 1.3).
*   **Audit Trail:** All fare searches and bookings logged with timestamp for compliance and revenue accounting.
*   **No Affiliate Tracking:** All pixels and scripts from third-party ad networks are blocked at the CDN level. Only direct carrier/CRS logos and data sources are displayed.
