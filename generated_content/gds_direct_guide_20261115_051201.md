## 1. Executive Summary

This guide provides a complete, end‑to‑end technical blueprint for:

- **Direct airline schedules** (Amadeus & Sabre Core Engine)

It also details how to expose this data via white‑label widgets (`[GDS_FLIGHT_SEARCH_WIDGET]` and `[CRS_HOTEL_INVENTORY_WIDGET]`) that can be embedded in partner sites or mobile apps, ensuring a friction‑free direct‑booking experience that preserves brand identity.

> **Key goals:**
> 1. **Zero dependency** on affiliate networks.  
> 2. **Real‑time accuracy** – live seat counts, cabin classes, and rates.  
> 3. **Seamless UX** – white‑label widgets that match your brand.  
> 4. **High conversion** – pricing transparency, instant booking flow.

## 3. Direct Airline Schedules

### 3.1 Data Source

| GDS | Protocol | Endpoints |
|-----|----------|-----------|
| Amadeus | REST (Amadeus One) | `/v1/shopping/flight-offers` |
| Sabre | XML (Sabre eTravel) | `Sabre_Air_Schedule_Query` |

### 3.2 Key Fields

| Field | Description | Example |
|-------|-------------|---------|
| `airlineCode` | IATA airline code | `TH` (Turkish Airlines) |
| `flightNumber` | Flight number | `TK1285` |
| `departureDateTime` | UTC datetime | `2026‑12‑15T14:00:00Z` |
| `arrivalDateTime` | UTC datetime | `2026‑12‑15T20:00:00Z` |
| `originLocationCode` | IATA city code | `IST` |
| `destinationLocationCode` | IATA city code | `LHR` |
| `cabinClass` | Economy, Premium Economy, Business, First | `EC` |
| `availableSeats` | Live seat count per cabin | `25` |

### 3.3 Implementation Notes

1. **Caching Layer** – Cache schedule data for 5 min using Redis; invalidate on `availableSeats` change.  
2. **Incremental Updates** – Use GDS “Seat Map” updates for dynamic seat availability.  
3. **Fallback** – If an airline does not support live seat reporting, expose a “Check Availability” button that triggers a real‑time seat inquiry before booking.

## 4. Live Cabin Class Availabilities

### 4.1 Data Model

```json
{
  "cabinClass": "EC",
  "totalSeats": 350,
  "availableSeats": 25,
  "fareFamily": "Standard",
  "fareRules": [
    {"ruleId": "R001", "description": "Non‑refundable"},
    {"ruleId": "R002", "description": "No change fee"}
  ],
  "fareAmount": {
    "currency": "EUR",
    "amount": 120.00
  }
}
```

### 4.2 Real‑Time Seat Inquiries

- **Amadeus** – `Seat Map` API (`/v1/shopping/seat-map`)  
- **Sabre** – `Seat Availability Inquiry` XML  

**Best Practices**

| Task | Recommendation |
|------|----------------|
| **Seat Map Request** | Batch requests for multiple itineraries to reduce latency. |
| **Error Handling** | Return `204 No Content` if no seats; trigger fallback to alternative cabin. |
| **Rate Limits** | Respect GDS limits (e.g., 200 req/min); implement exponential back‑off. |

## 5. Official Hotel CRS Rates (IST)

### 5.1 Data Source

| CRS | Protocol | Endpoints |
|-----|----------|-----------|
| Amadeus | REST (`/v1/shopping/hotel-offers`) | Hotel offers for IST |
| Sabre | XML (`Sabre_Hotel_Search`) | Hotel rates for IST |

### 5.2 Key Fields

| Field | Description | Example |
|-------|-------------|---------|
| `hotelCode` | Proprietary hotel identifier | `H12345` |
| `hotelName` | Hotel name | `Sultanahmet Hotel` |
| `roomType` | Room description | `Deluxe Double` |
| `ratePlan` | Rate plan code | `RP01` |
| `availableRooms` | Live availability | `3` |
| `rate` | Real‑time rate (incl. taxes) | `EUR 95.00` |
| `currency` | ISO 4217 | `EUR` |
| `stayDates` | `checkIn`, `checkOut` | `2026‑12‑10` / `2026‑12‑15` |

### 5.3 Pricing Transparency

- Show **exact** breakdown: base, taxes, fees, optional services.  
- Enable **price comparison** across multiple CRS sources (Amadeus vs Sabre) if both are configured.

## 6. White‑Label Direct Booking Integration

### 6.1 Widget Placement

```markdown
<!-- Flight Search Widget -->
[GDS_FLIGHT_SEARCH_WIDGET]

<!-- Hotel Inventory Widget -->
[CRS_HOTEL_INVENTORY_WIDGET]
```

> **Note:** Replace the placeholders with the actual iframe or JavaScript SDK that your portal will embed.

### 6.2 Widget API Contracts

| Widget | API Endpoint | Method | Required Headers | Payload |
|--------|--------------|--------|-------------------|---------|
| `[GDS_FLIGHT_SEARCH_WIDGET]` | `/api/search/flights` | POST | `Content-Type: application/json`, `X-Auth-Token` | `{ origin, destination, departureDate, returnDate, passengers, cabinPreference }` |
| `[CRS_HOTEL_INVENTORY_WIDGET]` | `/api/search/hotels` | POST | `Content-Type: application/json`, `X-Auth-Token` | `{ cityCode, checkIn, checkOut, guests, roomType, maxPrice }` |

### 6.3 Security & Authentication

- **OAuth 2.0** – each widget request must include a bearer token issued by the Core AI Engine.  
- **TLS 1.3** – all data in transit is encrypted.
