*Authoritative, Technical, Conversion‑Focused*

### 1. Overview  

This guide is built on **live, direct feeds** from the **Amadeus & Sabre Core Engines** and the **Central Reservation Systems (CRS)** that power hotel pricing for Istanbul (IST). No third‑party affiliate data is used – every data point originates from the carrier or hotel’s own reservation system, guaranteeing 0 % affiliate dependency.

### 2. Direct Airline Schedules & Live Cabin Class Availability  

| Data Element | Source | Refresh Frequency | Typical Latency | Key API Endpoint |
|--------------|--------|-------------------|----------------|------------------|
| **Carrier Flight Schedules** | Amadeus / Sabre Core Engine | Every 30 seconds (incremental) | ≤ 1 s | `/gds/v1/schedules` |
| **Cabin Class Inventory (Y, M, W, J, F, etc.)** | Amadeus / Sabre Core Engine | Real‑time push via **PUSH‑N‑PULL** | ≤ 2 s | `/gds/v1/inventory` |
| **Fare Construction & Taxes** | Amadeus / Sabre Core Engine | Real‑time (per‑PCC) | ≤ 2 s | `/gds/v1/fares` |
| **Seat Map & Ancillary Options** | Amadeus / Sabre Core Engine | On‑demand (per‑flight) | ≤ 3 s | `/gds/v1/seatmap` |

#### 2.1 Technical Highlights  

* **Binary PNR Retrieval** – Direct access to the carrier’s PNR database via **EDIFACT** and **OTA** messages, enabling instant confirmation without a middle‑man.  
* **Cabin‑Class Granularity** – Availability is returned per‑segment, per‑cabin, with **booking class codes** (e.g., Y, M, W) and **seat‑level inventory** (e.g., 12A, 12B).  
* **Dynamic Pricing Engine** – Uses carrier‑published **Fare Rules** (Rule‑Based Pricing, Fare‑By‑Rule, and Fare‑By‑Mileage) to compute the most competitive price at the moment of request.

* **Dynamic Rate Updates** – Supports **rate‑change events** (e.g., occupancy‑based pricing) that are pushed to the portal instantly via **WebSocket** channels.

### 7. Sample End‑to‑End Flow (Flight)  

1. **User enters origin, destination, dates** → `[GDS_FLIGHT_SEARCH_WIDGET]` fires a **POST** to `/gds/v1/search`.  
2. **Gateway** validates JWT, forwards request to **Amadeus/Sabre adapters**.  
3. **Adapters** query the Core Engine, receive **flight‑segment list + cabin‑class inventory**.  
4. **Pricing engine** enriches each option with **fare breakdown** and **taxes**.  
5. **Response** streamed back to widget (WebSocket) → UI updates in < 500 ms.  
6. **User selects a fare** → widget sends **PNR creation** request to `/gds/v1/pnr/create`.  
7. **Adapter** creates a **PNR** in the carrier’s system, returns **record locator** and **ticketing status**.  
8. **Confirmation page** displays **direct carrier ticket** with no markup.  

---  

### 8. Sample End‑to‑End Flow (Hotel)  

1. **User selects check‑in/out dates** → `[CRS_HOTEL_INVENTORY_WIDGET]` calls `/crs/v1/hotels/IST/rooms`.  
2. **Gateway** authenticates, forwards to **Hotel CRS adapters**.  
3. **Adapters** return **room‑type list**, **rate plans**, **availability**, and **instant‑confirm flag**.  
4. **Widget** renders options with **transparent tax breakdown**.  
5. **User books a room** → widget posts to `/crs/v1/reservations/create`.  
6. **Adapter** writes reservation directly into the hotel’s CRS, returns **confirmation number**.  
7. **Portal** shows **direct hotel confirmation** (no OTA ID).
